## Decisions and facts easy to get wrong after a compact
- Crate deps: app → sim + bevy (+ optional `serde_json` under `devtools`); cli → sim, data, core, png, serde; mcp → cli, serde_json. `omnis_sim` re-exports `omnis_core` and `omnis_data`; `omnis_cli` re-exports `omnis_sim`. New crates go in `Cargo.toml` members and `scripts/lint-sim.sh` `SIM_CRATES` (sim crates only) in the same change.
- The client protocol is `omnis_sim::ops`: `Op` (adjacently tagged, `{"op": "game.status"}`, `{"op": "sim.command", "args": {"command": {"Step": "Forward"}}}`), `Reply` (untagged), `OpError` (tagged `kind`: `Rejected`, `UnknownMap`, `TooLong`, `TooMany`, `HostOnly`, `BadRequest`, `Failed`), `dispatch(world, data, op)`; host ops `save.write`, `save.read`, `pack.reload`, `screenshot` are refused by `dispatch` and handled by `omnis_cli::Headless::handle` and the app's `socket::handle`. `ops::client_path(path, &["ron"])` is the shared path check (relative, no `.`/`..`, extension).
- Dev socket (`crates/omnis-app/src/socket.rs`, feature `devtools`): on by default at `127.0.0.1:0`, address in `.omnis/dev.addr`, `--dev-socket <ip:port>` / `--no-dev-socket`; lines `{"id", "op", "args"}` → `{"id", "ok", "result" | "error"}`; a missing `args` reads as `{}` and an empty `args` is dropped on argument-free ops (serde wants each the other way round); `MAX_LINE` 1 MiB; one client, extras get a `BadRequest` line and are closed; `screenshot` replies when `ScreenshotSaved` lands. Socket commands re-publish `SimEvent`s so the viewport and HUD follow.
- Bridge (`crates/omnis-mcp`): `omnis-mcp [--headless [--pack d]... [--seed n]] [--root dir] [--addr ip:port] [--addr-file f] [--log f]`; legacy `initialize` versions `2025-11-25`…`2024-11-05`, modern `2026-07-28` per request (`server/discover` → `supportedVersions`, `capabilities`, `instructions`, `_meta` serverInfo; `resultType: "complete"` on every modern result; `-32022` with `data.supported` on an unknown version; `-32602` when `_meta` lacks `clientCapabilities`). Tools: `game_status world_query sim_command sim_script events_tail viewport_get map_text automap_get save_write save_read pack_reload screenshot`. Screenshot bytes are read from `<root>/<path>`. `.mcp.json` passes `--root ${CLAUDE_PROJECT_DIR} --log ${CLAUDE_PROJECT_DIR}/.omnis/mcp.log`; the binary must exist at `target/debug/omnis-mcp`.
- CLI: `omnis-cli validate <dirs>`, `schema dump`, `map text <id> [--pack d]`, `play --script f [--pack d] [--seed n]`, `replay <file> [--pack d]`, `tileset bake <spec>...`; default pack `packs/test`. Script words: `forward back left right turn-left turn-right around use`, commas or whitespace, `#` comments (`omnis_sim::command::parse_script`); the app's `--script` adds `map save load`. CI runs the golden replay through the binary.
- Hand check of the whole stack: `cargo run -q -p omnis-app -- --seed 1 --window 1280x720 &`, wait for `.omnis/dev.addr`, pipe JSON-RPC lines into `./target/debug/omnis-mcp --root .`, then `pkill -f "omnis --seed"`.
- Maps are a text grid (`crates/omnis-data/src/map.rs`); `query::map_text` renders the same format with door state and the party marker `^ > v <`, open doors `_` and `'`. Any edit to `packs/test` needs `cargo test -p omnis-sim rebaseline -- --ignored` in the same commit; tilesets are baked (`omnis-cli tileset bake packs/test/bake/*.ron`). Dungeon: detail 6, width 5, visibility 6; outdoor: detail 4, width 3.
- Viewport geometry: focal `0.9 × 135 = 121.5` px, a face at distance `z` is `121.5/z` px tall; canvas 320×180, viewport 240×135, sidebar minimap (248,8,64,64), overlay on M. Window screenshots are black on this machine; `--screenshot-canvas` and the socket's `screenshot` (canvas) are the trusted captures.
