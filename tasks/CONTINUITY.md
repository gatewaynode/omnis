## Decisions and facts easy to get wrong after a compact
- Viewport cone (`crates/omnis-sim/src/visibility.rs`): row `d` spans offsets `-(d+1)..=(d+1)` because a face at distance `z` is `121.5/z` px tall and the canvas edge lies at offset `0.99 z`; line of sight through the shared edge hides a neighbour behind a wall, but the corner rule can see a neighbour past a wall through the tile in front or behind. The baker (`crates/omnis-cli/src/bake.rs` `slot_positions`) clamps that to the tileset width and `render` returns `None` for off-screen slots (a neighbour's outer side wall), so no sprite is written. Planner row order (`crates/omnis-app/src/plan.rs`): floors/ceilings, fronts, side walls, blocks; outer offsets first. A block beside the party renders as its side face only.
- Sprite counts: dungeon (detail 6, width 5) 317, outdoor (detail 4, width 3) 173. Any `packs/test` change needs `cargo test -p omnis-sim rebaseline -- --ignored` in the same commit; tilesets are baked (`cargo run -p omnis-cli -- tileset bake packs/test/bake/dungeon.ron packs/test/bake/outdoor.ron`), never hand-edited.
- Crate deps: app → sim + bevy (+ optional `serde_json` under `devtools`); cli → sim, data, core, png, serde; mcp → cli, serde_json. `omnis_sim` re-exports `omnis_core` and `omnis_data`; `omnis_cli` re-exports `omnis_sim`.
- Client protocol `omnis_sim::ops`: `Op` adjacently tagged (`{"op": "game.status"}`, `{"op": "sim.command", "args": {"command": {"Step": "Forward"}}}`), `Reply` untagged, `OpError` tagged `kind`; `dispatch(world, data, op)`; host ops `save.write`, `save.read`, `pack.reload`, `screenshot` refused by `dispatch`, handled by `omnis_cli::Headless::handle` and the app's `socket::handle`. M3's `party.*` and `rules.*` ops go in the same enum; the bridge's tool list (`crates/omnis-mcp/src/tools.rs`) and `schema dump` follow.
- Dev socket (`crates/omnis-app/src/socket.rs`, feature `devtools`): loopback, `127.0.0.1:0` default, address in `.omnis/dev.addr`, `--dev-socket <ip:port>` / `--no-dev-socket`; newline JSON `{id, op, args}` → `{id, ok, result | error}`; a missing `args` reads as `{}`, an empty one is dropped on argument-free ops; 1 MiB lines; one client; screenshot reply waits for `ScreenshotSaved`.
- Bridge (`crates/omnis-mcp`): dual era per request (legacy `initialize` 2025-11-25…2024-11-05; modern 2026-07-28 `server/discover`, `resultType: "complete"`, `-32022`); `.mcp.json` is a `sh -c` launcher with `root="${CLAUDE_PROJECT_DIR:-$PWD}"` because Claude Code 2.1.269 does not expand the `command` field; it speaks the legacy era and starts the server in the project root. The binary must exist at `target/debug/omnis-mcp`. `Visible` events are compacted to `{"count": n}` in tool results.
- CLI: `omnis-cli validate <dirs>`, `schema dump`, `map text <id> [--pack d]`, `play --script f`, `replay <file>`, `tileset bake <spec>...`; default pack `packs/test`. The app's `--script` is **comma-separated** (`forward,forward,turn-left,use,around`, plus `map` = toggle automap, `save`, `load`); there is no teleport, so captures walk from the start (16,16) north: 10 forward to (16,6); the portal at (16,5) lands at dungeon (1,0) south.
