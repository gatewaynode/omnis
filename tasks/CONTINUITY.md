## Decisions and facts easy to get wrong after a compact
- Owner decisions 2026-09-13: viewport visible in combat with generated silhouettes (CC0 art later, no layout change); permadeath on = a dead member leaves the party at combat end, kit to the party inventory; off = stays in the slot with `dead` for the M7 temple; a wipe reloads the last save (D14, app side). Roll log is a four-line tail.
- Bevy `Messages<M>` live two frames: tests collect them with a reader ordered `after(SimSet::Publish)`. `ButtonInput::clear()` keeps a key pressed; use `reset_all()`. A click or key takes two `app.update()`s; a state change one more. Socket commands bypass the `PlayState` run condition. Taking `&mut` on a `ResMut` marks it changed even without a write: `Res::is_changed` on a resource another system derefs mutably each frame is always true (the notice bug fixed in `7445a60`).
- Deprecated in Bevy 0.19's `SystemCondition`: `.and`/`.or`; use `.and_then`/`.or_else`.
- Sentrux: scan `crates/`, `max_fn_lines 100` incl. tests (the free tier checks a subset of the rules: measure by hand with the awk one-liner in the session or split anything near 100), `max_cycles 0`, no `omnis-app → omnis-data/core` imports. `menu.rs` 905 lines, `screens.rs` 624, `screen.rs` 541, `ui.rs` 430: new models go in new files. rustfmt rewraps `use` blocks, long calls, and test literals: read the region before patching, and anchor on function names for big replacements (a whole test was clobbered once this session by a region replace between two test names).
