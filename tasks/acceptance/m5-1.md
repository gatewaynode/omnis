# Acceptance: the notes store and the in-memory resolve (M5.1)

The first step of M5 Editor v1 (`tasks/plans/m5-editor-v1.md`). Nothing the player sees changes. Two things the
editor will stand on landed: a keyed store for the author's notes, and the loader's per-map resolution shared with
a path that resolves a map definition in memory, against loaded packs, without touching disk.

**Owner's direction (2026-10-21):** notes are not a text on each map and level (4 KiB would not hold a campaign's
notes, and one text cannot address a square). They are `notes/*.ron` files in the pack, a key to a text each, so
every square, object, item or other thing can carry a game master's note. Not sealed: a note changes no
fingerprint. A key whose target does not exist is allowed; the editor will mark it.

## What was built
- `notes/*.ron`: `(schema: 1, entries: { "<key>": "<text>" })`. A key is a content id (`base:item:mace`,
  `test:map:town`) or a content id followed by `/` and a path inside it: `test:map:town/0/3,1` the cell (3, 1) of
  level 0, `test:map:town/level/-1`, `test:map:town/chest.1` a placement, `test:map:town/terrain/r`. Each text at
  most 4 KiB, 65,536 entries and 4 MiB a file, any number of files. The loader reads and checks every notes file
  (schema, key shape, limits) and refuses a broken one like any other file; it hashes none of them and keeps none.
- `MapData::resolve(&MapDef, &Data)`: the same checks the loader runs on a map file (shape, layout, levels,
  stairs; then surfaces, text keys, portals, encounters, sites, rest events, objects, beings, region), plus the
  other maps' portals landing on this one and this map's portals landing among the other maps' objects. The
  loader's own loop calls the same function (`map_data::resolve_one`), so the two cannot drift.
- The loader's per-file steps the RON editor will reuse are their own functions: `parse_checked` (parse and
  schema), `check_manifest`, `check_text_file`.

## Steps
1. `cargo test -p omnis-data --test integration resolve`
   *You will see* six tests pass: every map of `packs/base` + `packs/test` and of the `levels`, `heights` and
   `objects` fixture packs resolves in memory to exactly what the loader built; a missing name key, a new map
   with no region, a bad shape, a portal landing outside its destination and another map's portal landing outside
   this one are each refused in the loader's words.
2. `cargo test -p omnis-data --test integration bad_packs`
   *You will see* the broken corpus pack report three new rows from its `notes/bad.ron` (two bad keys, one text
   over the limit) with every other row unchanged, and no seal complaint: the file was added without resealing,
   which is the proof that notes are not hashed.
3. `cargo test -p omnis-data notes`
   *You will see* the key rule's unit tests pass (`is_note_key`).
4. `cargo run -p omnis-cli -- validate packs/base packs/test`
   *You will see* `ok:` with the same counts as before: no shipped file changed.
