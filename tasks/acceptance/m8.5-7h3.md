# Acceptance: saves by name (M8.5 7h3)

This is the script for accepting M8.5 sub-step 7h3, the third of 7h (saves by name; the re-scope is at the
top of `tasks/plans/m8.5-saves-by-name.md`).
- **A save loads on other packs by name.** A load first rebuilds the save in its own numbering, through its
  world folder's name table, and checks it against its fingerprint on any packs (before, a forced load on
  other packs skipped that check). Then it fits the world to the loaded packs:
  - **the same packs:** as before;
  - **other packs with the same names** (only content changed, a map's layout or a text): the world records
    the new packs, and nothing is renumbered;
  - **other names:** every number the live world holds is renumbered by its string id. That covers the
    party, its sheets, tactics and effects, the maps' states, the automap (terrain by name), the objects
    (their spent interactions by verb, label and state), an encounter, a fight or a service, the clocks,
    contacts and time streams. The world then folds ("The world has moved on"): its journal goes to the
    archive in its old numbering, under its old world folder, so history is never renumbered.
- **A name the loaded packs lack refuses the load**, listing every one and where the save holds it. Nothing
  is dropped; the migrations (7h6) will offer what to do.
- **A save made before 7h2** (no name table) still loads on other packs only when forced, numbers as written.

**What moved:** nothing on disk. No golden moved and no pack was resealed. The `ahead` fixture pack is new
(`crates/omnis-sim/tests/packs/ahead`). It holds one copy of each kind a save numbers, under an id that sorts
first, so with it loaded every number the other packs had moves up.

## Steps
1. From the repository root, start the game on the base, test and objects packs:
   ```
   just run --windowed --pack packs/base --pack packs/test --pack crates/omnis-sim/tests/packs/objects
   ```
   Start a **New game** with a party that has a wizard. Open the wizard's sheet and note their spells and
   their kit. Walk a few steps out of town, then Esc, **Save**.
2. Quit, and start again with `ahead` added:
   ```
   just run --windowed --pack packs/base --pack packs/test --pack crates/omnis-sim/tests/packs/objects --pack crates/omnis-sim/tests/packs/ahead
   ```
   On the title, choose **Load quick save**.
   *You will see* "Loaded .omnis/quick.ron: … applied in … ms; made with other packs, loaded by name. The
   world has moved on". The party stands where it saved.
3. Open the wizard's sheet.
   *You will see* the same spells and the same kit as in step 1, though every spell's and item's number
   moved.
4. Esc, **Debug**, the **World** page.
   *You will see* "Manifest: … names". The count is higher than with three packs, since it counts the names
   of the packs now loaded.
5. The refusal. On the Debug panel's **Party** page, choose **Item**: the first entry is **Dagger**, the
   `ahead` pack's copy, listed first because its id sorts first. Set Count 1 and choose **To stores**. Close
   the panel, Esc, **Save**, then quit.
6. Start the game as in step 1 (without `ahead`) and choose **Load quick save**.
   *You will see* the load refused: "save names what the packs no longer have: item 'ahead:item:dagger' in
   party.inventory". The window stays on the title.
7. Optional: start as in step 2 (with `ahead`) and **Load quick save**.
   *You will see* "1 interaction applied …" or similar with no "other packs": the save was made on these
   packs.

## What the tests cover
- **`omnis-sim/tests/by_name.rs` (11):**
  - `ahead` moves every kind a save numbers: maps, flags, regions, items, spells, monsters, conditions,
    races, classes, backgrounds and services;
  - a save loaded under `ahead` reads the same through every view (party, viewport, fight, service, rest,
    cast, objects, clocks, automap, the log, the flags, `here`), and by name where no view looks (the time
    streams, the clocks and contacts, the bus, the maps' cleared groups and objects, the party's knowledge,
    every automap tile's terrain, the retreat and the loot, the log's maps). That holds exploring after the
    rats' fight, mid-fight (the fight goes on after), in three services, and in the yard of objects. The
    world folds, its journal held for the old folder; saved again it loads as the same world, and tidy lists
    nothing of the old folder;
  - a save holding `ahead`'s dagger is refused without it, each place listed;
  - terrain and interaction rows are found by name and signature through a moved table;
  - a save altered on disk is refused on other packs (the fingerprint is checked there now);
  - a stream between two regions whose numbers trade places is put back in order;
  - a pack the save never used may go, and the bus keeps no topic of a region gone;
  - a base of a region the packs lack is refused by name, with its map.
- **`disk.rs`:**
  - a save loads on other packs by name, unforced; the same save with its name table removed is refused
    unless forced, then loads as written;
  - the converted schema 7 save, saved again, loads with the same names on other packs (`Content`).
- **`omnis-bus`:** `Bus::retain` keeps the topics it accepts, in order.
- **Mutations (38 of 38 caught):** each renumbered field left as written, one by one (position, map states
  and their piles, contents and spent interactions, automap keys on every level and terrain rows, the
  knowledge, the encounter's stacks, retreat and loot, the service, flags, clocks, contacts, time streams and
  their order, the bus, the party's stores and effects, every sheet field and the tactics); the log's maps;
  the fold; the same-names tier; the fingerprint on other packs; region bases read through the table.
