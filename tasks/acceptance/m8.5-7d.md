# Acceptance: the character save and the world folder (M8.5 7d)

This is the script for accepting M8.5 sub-step 7d (`tasks/plans/m8.5-save-model.md`). A save is no longer the
whole world (PRD D28). The quick save `.omnis/quick.ron` is now a **character save**, which holds:
- the party at the world's base;
- the commands since, written in runs ("step ×6");
- the names of the bases it starts from;
- the fingerprint the replay must reach.

The world's bases sit in a **world folder**, `.omnis/worlds/<id>/`:
- `manifest.ron` (the seed and packs);
- `world/<hash>.ron`;
- `regions/<pack>/<name>/<hash>.ron`, each named by the hash of its text.

**Loading** joins the bases and replays the commands. **An older save** (schema 7 and before, a whole world)
loads by becoming the base of a new, empty journal. `SAVE_SCHEMA` is now 8.

**Measured** (release, the 7a wander):

| Commands | Save, as written (compact, in runs) | Same save, pretty | The 7a journal, raw | Load |
|---|---|---|---|---|
| 10,000 | 120 KB | 306 KB | ~670 KB | 0.2 s |
| 50,000 | 605 KB | — | — | 1.8 s |

The 4 MiB file limit now holds about 340,000 commands, so load time is what folds must bound (7e).

**Choices of mine:**
- **A replay that fails stops the load**, with the command and the refusal. "Load without it, or cancel" needs
  a changed pack, which loading still refuses until 7h.
- **The character save is one line of compact RON.** The manifest and bases stay readable.
- **The world folder is named from the seed and packs.** Two new games with the same seed and packs share it.
  Until there are folds (7e), a new game's base is the packs themselves (no file), so a save replays from the
  start. Only a converted old save writes base files.
- **A save is a record of commands.** A party set down or changed by hand (the tests' helpers) cannot be
  replayed, so such tests first make the world their base, as a fold will.
- **Developer-only gap:** `rules.set` and `pack.reload` over the dev socket change the rules without a command,
  so a save made after them may not replay. Noted for 7e, where a fold can rebase at that moment.
- **Rebaseline:** both golden replays were rebaselined: their fingerprint text carries the schema number. Walk
  is now `d9f7bb81ad3a7a25`, fight `69264fcb84cbbb06`; the commands are unchanged.

**Start.** **First copy your current quick save aside**, e.g. `cp .omnis/quick.ron .omnis/quick-v7.ron`. It is a
schema 7 save made with the objects pack, and the first new save overwrites it. Then run `just run --windowed --pack packs/base --pack
packs/test`.

## Steps
1. Start a new game and make a party. Walk a few cells, open a door, then Esc and **Save**.
   *You will see* "Saved to .omnis/quick.ron". Run `ls -R .omnis/worlds` in a terminal: a folder with a
   sixteen-letter name holding `manifest.ron`. `.omnis/quick.ron` is one long line.
2. Quit to the title (or quit the game and start it again), then **Load**.
   *You will see* "Loaded .omnis/quick.ron: replayed N commands in T ms", and the party where it stood, the
   door open.
3. Mid-fight: walk until something attacks, take a turn, Save, then Load.
   *You will see* the fight resume on the same turn.
4. An old save. Quit, run `cp crates/omnis-sim/tests/saves/v7.ron .omnis/quick.ron` (the committed schema 7
   fixture, made on today's base and test packs), start the game, and Load from the title.
   *You will see* "Loaded .omnis/quick.ron: converted from a schema 7 save", and the party at the dungeon's
   first door, the door open.

   **Your own old quick save will be refused**, with "save was made with different packs". It was made with
   the objects pack loaded, and that pack changed in 7c (its flag files). The window never forces a load, so
   such a save waits for 7h, which loads across pack changes. Keep the copy you made.
5. Save again, then run `ls -R .omnis/worlds`.
   *You will see* a second world folder (your old game's seed), now with `regions/…/<hash>.ron` files: the
   old world, made a base. Load once more: "replayed 0 commands …" for the moment just converted, or more if
   you walked first.

## What the tests cover
- `omnis-sim/tests/disk.rs` (9 tests):
  - a new game's save names no bases and replays its journal;
  - both goldens save and load after every command (explore, encounter, combat), as do an inn and mid-fight;
  - a repeat is one run;
  - a run of none, a journal past 1,000,000 commands, a refused command, a wrong fingerprint and a world name
    that climbs out of the folder are each refused, the last before any file is read;
  - other packs are refused unless forced;
  - the v7 fixture converts and saves its region bases, in order, and loads back; a base altered by one byte,
    or missing, is refused;
  - v1 to v7 all convert;
  - the save rule holds.
- `omnis-data/tests/files.rs`: files are written whole, a base already there is kept, no temp file is left
  behind, and a path out of the root is refused both ways.
- The headless round trip, the client's save limits, the socket's save and read, and the screens' quick save
  and load, all through the new files.
- 10 mutants killed: the base hash, runs, run lengths, the cap, conversion's origin, the fingerprint, the save
  rule, the order of files, kept files, the world name.
