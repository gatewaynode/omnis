# Acceptance: the save check and the Load screen (M8.5 7h4)

This is the script for accepting M8.5 sub-step 7h4, the fourth of 7h (saves by name; the re-scope is at the
top of `tasks/plans/m8.5-saves-by-name.md`).
- **A load is examined first.** The engine rebuilds the save and works out what the loaded packs make of it,
  changing nothing. The result is a report with one of five verdicts:
  - `same`: the packs it was made with;
  - `content`: other packs, every name the same;
  - `renamed`: other packs whose names moved;
  - `unresolved`: it names what the packs lack;
  - `unnamed`: other packs, and a save made before saves kept names.

  The report also gives each pack as saved and as loaded, how many names moved number, the missing names with
  where, and the places the maps no longer allow.
- **The window:** a save that loads, loads at once, in one click, as before. One that does not opens a new
  **Load screen** ("This save does not load"): the packs that changed, then each missing name, 12 of each list
  shown and the rest counted, then **Close**, back where Load was pressed. Nothing is loaded.
- **Places load and warn** (your choice): on other packs, a party where it cannot stand moves to the nearest
  cell it can. What lies in the world is the world's (your rule, 2026-10-19): a pile whose ground went away is
  lost, and so are the items a container the map no longer places held. Only the party's inventory and stores
  are kept whatever the packs do. An open door no longer a door, a cleared encounter the map lost and automap
  tiles outside the map are dropped. Each warning is a line in the log, saying how many items were lost, and
  the world folds ("The world has moved on").
- **The op `save.check`** (`path`) answers the report; MCP `save_check` (27 tools).

**What moved:** ops 27, tools 27, replies 20; `PROTOCOL` stays 2. No golden moved and no pack was resealed.
`load_save` is now `examine` then `restore`, unchanged for every 7h3 case.

**Found while building:** dropping a cleared encounter or an automap tile changed the world without a warning.
Without a fold, the next save would have been refused as altered. The load now folds on any change the check
makes, and a test round-trips each fix through a second save.

## Steps
1. The refused load. From the repository root, start with `ahead`:
   ```
   just run --windowed --pack packs/base --pack packs/test --pack crates/omnis-sim/tests/packs/objects --pack crates/omnis-sim/tests/packs/ahead
   ```
   Start a **New game**. Esc, **Debug**, the **Party** page: choose **Item**, the first entry (**Dagger**,
   `ahead`'s), Count 1, **To stores**. Close the panel, Esc, **Save**, then quit.
2. Start without `ahead`:
   ```
   just run --windowed --pack packs/base --pack packs/test --pack crates/omnis-sim/tests/packs/objects
   ```
   On the title, choose **Load quick save**.
   *You will see* the Load screen:
   - "This save does not load";
   - "It names what the loaded packs no longer have.";
   - "Packs changed:", then "ahead: saved 0.1.1, loaded none";
   - "Missing:", then "item 'ahead:item:dagger' in party.inventory";
   - a **Close** button.
3. Choose **Close**.
   *You will see* the title again. Nothing was loaded.
4. Optional, the report by MCP: start a **New game** (the socket answers in a world), then ask me
   "save_check `.omnis/quick.ron`".
   *You will see* in my answer the verdict `unresolved`, `ahead` with `loaded` null, and the dagger under
   `missing`.
5. The clean load on other packs. Still without `ahead`, in that new game: Esc, **Save**, quit. Start with
   `ahead` (the command in step 1) and choose **Load quick save**.
   *You will see* no Load screen: the game loads at once, and the log reads "Loaded .omnis/quick.ron: …; made
   with other packs, loaded by name. The world has moved on".
6. A place the map no longer allows. Start without `ahead` (step 2's command), **New game**. Esc, **Debug**,
   the **World** page: Map `objects:map:yard`, x 2, y 2, Facing east, **Go**. Close the panel, Esc, **Save**,
   quit. Then make (2, 2) rock in a terminal:
   ```
   cp crates/omnis-sim/tests/packs/objects/data/maps/yard.ron /tmp/yard.ron
   cp crates/omnis-sim/tests/packs/objects/pack.ron /tmp/objects-pack.ron
   ```
   In `crates/omnis-sim/tests/packs/objects/data/maps/yard.ron`, make two edits:
   - add the terrain line `(glyph: 'r', name: "rock", floor: "road", ceiling: None, passable: false,
     visibility_depth: 6, step_minutes: 2),` after the ladder's;
   - in `layout`, change the third `|g g g g g g g|` row (row 2) to `|g g r g g g g|`.

   Then run `cargo run -p omnis-cli -- pack seal crates/omnis-sim/tests/packs/objects`, start as in step 2,
   and choose **Load quick save**.
   *You will see* the game load, and the log read:
   - "Loaded .omnis/quick.ron: …; 1 place changed, see the log; made with other packs, loaded by name. The
     world has moved on" (adding a terrain moves the yard's terrain names, so it loads by name);
   - "The party could not stand at objects:map:yard (2, 2); moved to (2, 1)."

   The party stands at (2, 1). (1, 1) is nearer in the search order, but a crate stands across its centre.
7. Put the yard back:
   ```
   cp /tmp/yard.ron crates/omnis-sim/tests/packs/objects/data/maps/yard.ron
   cp /tmp/objects-pack.ron crates/omnis-sim/tests/packs/objects/pack.ron
   git status --short crates/omnis-sim/tests/packs/objects
   ```
   *You will see* nothing listed.

## What the tests cover
- **`omnis-sim/tests/save_check.rs` (17):**
  - a report for each verdict: same, content, renamed (with how many names moved), unresolved (each name with
    where, `restore` refusing it even when forced), and unnamed (refused unless forced, then `Forced`);
  - `restore` refuses packs other than the ones examined against, even when both keep the save's names;
  - each place:
    - the party in rock moves to the nearest cell it can stand on, past a crate;
    - with nowhere to stand, the party goes to the map's start;
    - an open door no longer a door is forgotten;
    - a pile whose ground went away is lost, its items counted in the warning, the party's stores untouched;
    - what an object no longer placed held is lost, counted in the warning;
    - a cleared encounter the map lost is dropped silently, and kept while the map has it;
    - automap tiles outside the map are trimmed.

    Each fix is saved again and loads as the same world;
  - the report and the fixed world are the same every time;
  - the report reads back as written;
  - `moved` counts only names whose number changed.
- **Client (`omnis-vector/tests/load_report.rs`, 5):**
  - the refused save opens the Load screen with its rows and closes to the title, nothing loaded;
  - a save on other packs loads at once by name;
  - a place warning becomes a log line (the window's and the socket's load);
  - a save without names loads only forced;
  - the screen shows 12 of a list and counts the rest.
- **Socket:** `save.check` answers `check` with `same` and changes nothing.
- **Mutations (30 of 31 caught):** each verdict, the moved count, the missing list, the places reported and
  checked on content, the examined packs, the fold on any fix, the packs recorded, each pack's sides, every
  place rule and fix, the trims, the `moved` comparison, the window's refusal screen, its cap and Close, the
  forced load and the said line. One is equivalent: `Unnamed if force` cannot be reached unforced through
  the public API.
- **MCP and CLI:**
  - `save_check` among 27 tools, its example validated;
  - the `check` reply reads back without its op;
  - the op list (27) and every doc count pinned.
