# Acceptance: Playtest and Back to editor (M5.8)

The eighth step of M5 Editor v1 (`tasks/plans/m5-editor-v1.md` row 8, §Client side "Playtest"): a game on the
edited map as the editor holds it, the fixed party standing on the cursor's cell facing the cursor's way; the
editor's document untouched; Back to editor from Pause or Defeat.

**Accepted by the owner 2026-10-24** ("Tests well, accepted").

## What was built
- **Playtest** (the tools column, under Save and Revert) starts a game on the edited map with the fixed party
  (Brenna, Durin, Ilvara, Pip), teleported to the cursor's cell facing as the cursor does. The game plays a
  copy of the loaded packs with the editor's map put in; the packs themselves and the editor's document are
  never touched. The editor is parked whole while the game runs: its layer and preview go down, the 3D view,
  HUD and minimap take over.
- **Dim with its reason** when it cannot start: no map open; the loader refuses the map ("N errors: …", the
  same words as Save's); the cursor stands on no ground or on terrain that is not passable; a build without
  the dev tools (the teleport is theirs; release builds).
- **Pause in a playtest** offers Resume, Settings and Debug as ever; Save, Load and Save log are dim ("a
  playtest is not saved", "… not loaded"); **Back to editor** stands where Quit to title does; Quit stays.
  **Defeat** adds Back to editor beside Start again and Quit to title, Load dim likewise.
- **Back to editor** drops the game and brings the editor back exactly as left: cursor, facing, view, tool,
  the open form, the undo history, the dirty mark. Quit to title from the editor's menu afterwards leaves
  nothing parked.

## Steps
1. `cp -R packs/test /tmp/omnis-scratch`, `just run --windowed --pack packs/base --pack /tmp/omnis-scratch`,
   Editor, open the town. Click a street cell, press E to face east, paint a wall across the street ahead.
2. Click **Playtest**.
   *You will see* the 3D view from that cell facing east, the wall you painted standing in the street, the
   HUD and the minimap, the party of four. Walk; turn; the services' icons on the floor.
3. Press Esc.
   *You will see* PAUSED with Save "a playtest is not saved", Load "a playtest is not loaded", and **Back to
   editor** in the row where Quit to title stood. Click it.
   *You will see* the editor as you left it: the cursor on the same cell facing east, the wall painted, `*`
   in the title, Undo live. Undo takes the wall away.
4. Paint No ground under the cursor.
   *You will see* Playtest dim: "the cursor stands on no ground". Undo. Make the map invalid (a steep ramp):
   Playtest dim with the loader's words, as Save is. Undo.
5. Playtest again, Esc, **Back to editor**, Esc, **Back to title**.
   *You will see* the title; New game starts a fresh game on the packs as loaded (the wall is not there: it
   was never saved).

Covered by `tests/editor_playtest.rs` (the game plays the edited map at the cursor with the fixed party while
the packs stay as loaded; Pause's Back to editor and dim Save; the editor back as left; the dim reasons; Quit
to title after a playtest leaves nothing parked).

## Known and expected
- A playtest cannot be saved or loaded; its log is not kept. Save the map in the editor and start a New game
  from the title to play it for keeps.
- Reload (the debug page) in a playtest reloads the packs from disk into the game, dropping the edited map.
- Release builds (`--no-default-features`) have no dev tools and so no Playtest: dim with "needs the dev
  tools build".
