# Acceptance: the editor's ops and MCP tools (M5.3)

The third step of M5 Editor v1 (`tasks/plans/m5-editor-v1.md`): the document model of M5.2 reached from any
client of the engine's API. Seventeen `editor.*` ops, their replies, one error kind, and the MCP tools, all
additive: the protocol stays 2. The counts moved from 27 ops and tools to 44, 20 replies to 27, 10 error kinds
to 11, in every place the tests pin (`docs/api.md`, `README.md`, `code-map.md`, ARCHITECTURE §9.3).

## What was built
- `omnis_data::edit::{Request, Answer, answer}`: the editor's requests as one plain enum, answered over a
  `Session`, so a host is three lines.
- `omnis-sim/src/editor_ops.rs`: `Op::editor()` turns an `editor.*` op into a `Request` with its strings and
  paths bounded (`client_path`, `bounded`, the new `bounded_file` at 4 MiB for a file's text); an `Answer` becomes
  a `Reply`, an `EditError` an `OpError` (`Invalid { errors }` with the loader's words, `Failed` for I/O).
- `Headless` (the CLI, and `omnis-mcp --headless`) owns an `edit::Session` over the last pack loaded and answers
  the editor ops before anything else. A save or a write changes the pack on disk; `pack.reload` brings it under
  the running world. The game's socket follows in M5.4, when the client has an editor to host.
- MCP: 17 tools with hand-written schemas for `Brush`, `Place`, `Edit`, `NewMap` and the map file's structs
  they carry (`editor_schema.rs`); a test deserialises an instance of every branch.

## Steps (an agent against `omnis-mcp --headless`, on a copy of `packs/test` so the shipped pack stays sealed)
1. Copy the pack: `cp -R packs/test /tmp/omnis-edit` and start the bridge headless on it:
   `target/debug/omnis-mcp --headless packs/base /tmp/omnis-edit` (build with `cargo build -p omnis-mcp`), or point
   `.mcp.json` at those arguments for a session.
2. `editor_maps`
   *You will see* four entries, `test:map:depths`, `dungeon`, `meadow`, `town`, each with its file and no error.
3. `editor_open` with `map: "test:map:town"`
   *You will see* the `editor` reply: 12 by 5, level 0, nine terrains, `dirty: false`, `errors: []`.
4. `editor_paint` with `x: 1, y: 1, brush: {"Edge": {"side": "East", "kind": "Door"}}`
   *You will see* `dirty: true`, `undo: 1`, `errors: []`.
5. `editor_status`, then `editor_undo`, then `editor_redo`
   *You will see* the undo and redo depths move (1/0, 0/1, 1/0) and `dirty` follow them.
6. `editor_place` with `place: {"RestEvent": {"terrain": "street", "rest": "Short", "chance": 10, "text": "test:text:rest.nowhere"}}`, then `editor_save`
   *You will see* the status carry one error naming the missing text key, and the save refused with
   `Invalid` and that line; the file on disk is unchanged (`cat /tmp/omnis-edit/data/maps/town.ron`).
7. `editor_undo`, then `editor_save`
   *You will see* `written` with `path: data/maps/town.ron` and `version: "0.1.2"`; `/tmp/omnis-edit/pack.ron`
   says `version: "0.1.2"` with a new hash and its comment kept.
8. `pack_reload`, then `map_text` with `map: "test:map:town"`
   *You will see* the reload's `done`, and the door you painted as `:` east of tile (1, 1).
9. `editor_read` with `path: "data/maps/meadow.ron"`; change `width:` to `widt:` in the text; `editor_check` with it
   *You will see* `checked` with one line, `parse error` at its line number. `editor_write` with the same text is
   refused with `Invalid`; `editor_read` again shows the file untouched.
10. `editor_note_set` with `key: "test:map:town/0/1,1", text: "The inn's front room."`, then `editor_notes`
    *You will see* the key listed and no orphans; `/tmp/omnis-edit/notes/town.ron` holds it; `pack.ron` did not
    change (notes are not sealed). `editor_note_set` with `key: "test:monster:dragon"` then `editor_notes` lists
    it among the orphans.
11. `cargo run -p omnis-cli -- schema dump | grep -c editor`
    *You will see* 17 editor ops in the dump's op list.

## Not in this step
The game's own editor (M5.4 on) and the socket answering `editor.*` while it is open.
