# Acceptance: the RON text editor (M5.9)

The ninth step of M5 Editor v1 (`tasks/plans/m5-editor-v1.md` row 9): every other pack file as text, checked by
the loader's own functions before it is written exactly as typed, so comments survive and the loader and the
writer stay one code path (ARCHITECTURE §8.2).

**Accepted:** pending the owner's hand test.

**A Save file writes the pack on disk and reseals it.** Hand-test on a scratch copy: `cp -R packs/test
/tmp/omnis-scratch`, named as the last pack.

## What was built
- **Plan | Files** at the top of the tools column, the current one marked. In Files mode the column lists every
  file the loader reads (`pack.ron`, `data/**`, `text/**`, `notes/**`, `migrations/**`) as buttons, the open one
  marked, then **Check**, **Save file** and **Revert file**; Undo/Redo, the map's Save/Revert, Playtest and Menu
  stay. Plan returns to the map; the open file stays open for next time.
- **The text** fills the centre in place of the bar and the plan: one field of forty lines across the column
  (the panel scrolls for the rest; the wheel moves it), Enter breaks a line, the caret stays through every
  redraw. The field's limit is the file limit (4 MiB).
- **Check** asks the loader about the text as typed; the inspector reads the file, its size, `*` while it
  differs from disk, and the verdict: "not checked since the last change", "the loader takes this file", or
  the errors in the loader's words. Typing clears the verdict.
- **Save file** is dim with its reason: "choose a file", "no changes", "check first", or "N errors: …". It
  writes the bytes exactly as typed, reseals the pack (the version rises when the content changed) and
  reloads the packs; a note file is written but not sealed. When the file is the open map's own, the
  document is reopened as the file, the cursor, level, view and brush kept.
- **Revert file** puts the disk's text back and clears the verdict.
- A field of several lines (a note's four, the file's forty) now takes its row's whole width.

## Steps
1. Editor, open the town, click **Files**.
   *You will see* the file list in the tools column, "Choose a file" in the centre, the plan gone.
2. Click `text/en/maps.ron`.
   *You will see* the file's text across the centre, the caret in it, the inspector reading its size and
   "not checked since the last change" once you type. Scroll with the wheel.
3. Delete a quote mark, click **Check**.
   *You will see* the loader's words in the inspector and the tools column, Save file dim with them. Put the
   quote back, Check: "the loader takes this file".
4. Add a comment line at the top, Check, **Save file**.
   *You will see* "Wrote text/en/maps.ron; test sealed at 0.1.x"; the file on disk starts with your comment.
5. Open `data/maps/town.ron`, add a comment line, Check, Save file; click **Plan**.
   *You will see* the plan unchanged, the title without `*`: the map was reopened from the file you wrote.
6. Break the town's layout (shorten a row), Check: the loader's words; **Revert file**: the text as the file.

Covered by `tests/editor_files.rs` (the list and the centre, a broken edit checked and reverted, a checked
edit written as typed and resealed with the packs reloaded, the map's own file reopening the document and
dropping an unwritten paint, a note written without a seal) and `files.rs`'s unit test.

## Known and expected
- A file over 4 MiB cannot be typed past the limit (the field refuses the edit) and a text the loader
  refuses is never written. The RON editor checks one file at a time: a content file's references to other
  files are checked when the pack loads again (at Save file's reload, said in the tools column if it fails).
- The map's own file written reopens the document and drops any unsaved paint: save the map first.
