# Acceptance: schema 9 (M8.5 7h2)

This is the script for accepting M8.5 sub-step 7h2, the second of 7h (saves by name; the re-scope is at the
top of `tasks/plans/m8.5-saves-by-name.md`).
- **Fixed encounters have ids.** Every fixed encounter in a map now has a required `id` (`[a-z0-9_]{1,32}`,
  unique among the map's objects and encounters). A save keeps a cleared encounter by that id, not by its row
  in the map file, so reordering a map's encounters no longer clears the wrong group. A standing group's
  name is its encounter's id (`stand` lost its own `id`).
- **Save schema 9.** A schema 8 save (made before today) names rows. It loads with each row turned into the
  id that row has now, and is reported as converted. A row the map no longer has refuses the load.
- **The name table.** Every save now writes, in its world folder's manifest, what each of its numbers stood
  for: every kind's string ids, the party's flags, each map's terrains and each object kind's `once`
  interactions. 7h3 uses it to load a save on changed packs. Because the manifest changed, every save from
  now on writes a new world folder.
- **A bug fixed:** `pack.reload` never recorded the new packs on the world, so a save made after a reload
  claimed the old packs and was refused on the very packs it ran on. It records them now.
- **Base 0 is empty.** A save no longer needs the current packs to know what an untouched world holds.

**What moved:**
- The test pack's maps gained ids and the pack was resealed at 0.1.1, as were the objects fixture and two
  bad-pack fixtures.
- Both golden replays were rebaselined (pack hash, schema). Not one command moved.
- `EncounterStarted.source` and `CombatView.source` read `{"Fixed": "<id>"}` where they read a row number.
  Protocol stays 2.

**Before you start.** A save made before today names 7h1's packs, and the window never forces a load. So
step 2 is a forced load through the game's dev socket: ask me in this session and I call `save_read` with
`force`. This is the break you accepted for saves made before 7h.

## Steps
1. From the repository root, put the frozen schema 8 save in place:
   ```
   mkdir -p .omnis/saves .omnis/worlds
   cp crates/omnis-sim/tests/saves/v8-cleared/saves/folded.ron .omnis/saves/folded-v8.ron
   cp crates/omnis-sim/tests/saves/v8-cleared/saves/journal.ron .omnis/saves/journal-v8.ron
   cp -R crates/omnis-sim/tests/saves/v8-cleared/worlds/bc8439b42131abf8 .omnis/worlds/
   just run --windowed --pack packs/base --pack packs/test
   ```
   Start a **New game**; any party will do (the load replaces it).

   The fixture was made by the 7h1 build. The golden fight cleared the rats (row 0 of the dungeon's
   encounters), then the world folded, then the party stepped onto the goblins at (3, 14) (row 3).
2. Ask me: "load `.omnis/saves/folded-v8.ron` forced".
   *You will see:*
   - "Loaded .omnis/saves/folded-v8.ron: converted from a schema 8 save";
   - the encounter screen with two goblins, the party at (3, 14) of the dungeon.
3. Choose **Run**.
   *You will see* the party back at (3, 13), facing north. If the run fails and a fight starts, end it from
   Esc, Debug, the Fight page: **Kill** each stack.
4. Esc, **Debug**, the **World** page.
   *You will see* "Manifest: 109 names, what the save's numbers stand for" under the journal line.
5. Still on the World page, teleport: Map `test:map:dungeon`, x 3, y 7, Facing south, **Go**. Close the panel
   and step forward onto (3, 8).
   *You will see* no rats: they stay cleared, converted from their row to `giant_rat_3_8`. The dungeon's
   random table fires on 3% of steps; if wandering monsters appear instead, end them (Run, or Kill from the
   Fight page) and step onto (3, 8) again.
6. Optional, the journal case: ask me to load `.omnis/saves/journal-v8.ron` forced. That save was made
   straight after the fight, before the fold, so the rats' clearing is in its journal, not its base. Step off
   (3, 8) and back on.
   *You will see* "converted from a schema 8 save", and no rats.
7. Optional, the name table on disk: Esc, **Save**, then in a terminal run `ls .omnis/worlds`.
   *You will see* a second world folder beside `bc8439b42131abf8`. Its `manifest.ron` has a `names:` section
   listing `test:map:dungeon` among the maps.

   That save still names 7h1's packs: a forced load keeps the numbers and packs as written. So the window
   refuses it until 7h3 loads saves by name.

## What the tests cover
- **`omnis-sim/tests/by_id.rs` (10):**
  - the schema 8 fixture's journal, base, encounter and log rows become ids;
  - a converted save saves as schema 9 and loads back unforced, the same world;
  - a row the map lacks refuses the load, naming the map and the row;
  - a whole-world save (schema 7) clears by id too;
  - a schema 8 save on its own packs loads unforced (its fingerprint was taken of rows);
  - tidy counts schema 8 saves, so their files are never listed;
  - the name table holds every kind in number order, the party's flags, terrains and `once`
    interactions; a manifest without one keeps its world's name.
- **`fold.rs`:**
  - after a reload, a save loads unforced and names the segment in the old folder;
  - tidy keeps the old folder's segment and manifest;
  - a segment held from another world is written in that world's folder.
- **`ops.rs`:** a reload records the packs, and a refused one changes nothing.
- **`split.rs`:** a new world splits into `Bases::default()` on both the test and the objects packs.
- **`disk.rs`:** the frozen schema 9 save `tests/saves/v9/` (the golden fight, folded halfway) loads as
  written, with its manifest's names; the schema 8 fixture converts.
- **Data:** a duplicate encounter id is a bad-pack row; the bad ids moved from "being" to "encounter".
- **Client:** the World page shows the name count.
- **Mutations (16 of 16 caught):**
  - a reload not recording the packs;
  - a segment's folder kept or dropped wrongly, and a held one written in the wrong folder or without its
    manifest;
  - tidy not naming another folder's manifest, or skipping schema 8 saves;
  - each row conversion skipped: the marker, the journal, the encounter, the log, the whole world;
  - a converted save held to its fingerprint;
  - base 0 no longer empty;
  - the duplicate-id check;
  - a cleared encounter not skipped.
