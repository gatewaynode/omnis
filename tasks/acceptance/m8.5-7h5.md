# Acceptance: reload by name (M8.5 7h5)

This is the script for accepting M8.5 sub-step 7h5, the fifth of 7h (saves by name; the re-scope is at the top
of `tasks/plans/m8.5-saves-by-name.md`).
- **A reload is a load of the running world.** Before, `pack.reload` checked only that the party's tile still
  existed and recorded the packs. A pack that added a definition sorting first renumbered every later id under
  the running game without a word: the wizard's spells became other spells. Now the running world is fitted to
  the packs on disk as a save made on the packs it runs on would be on load, through the same code
  (`save::examine_running`, then `save::restore`):
  - the same packs change nothing (`same`);
  - other content with every name the same records the packs (`content`);
  - moved names renumber the world by name, and it folds ("The world has moved on"; `renamed`), its journal
    kept for the old world folder;
  - places the fresh maps no longer allow load and warn (your 7h4 choice; the old refusal for a lost party tile
    is gone);
  - a name the fresh packs lack refuses the reload, each name listed, and nothing changes.
- **The reply** (your choice): `done` gains `check`, the reload's report; `PROTOCOL` stays 2, and a `done`
  without it still reads.
- **The window** (your choice): the Debug page's World tab gains **Reload packs** beside Fold and Tidy. The log
  says how the reload went ("Packs reloaded: ...") and each place it changed. A refused reload opens the Load
  screen, titled "These packs do not load", and Close returns to the Debug page.
- **Both hosts** (the socket in the window and the headless driver) only load the packs and call
  `ops::reload`; the window's session (`Session::reload`) is shared by the socket and the button.

**What moved:** ops 27, tools 27, replies 20; `PROTOCOL` stays 2. No golden moved and no pack was resealed.
`ops::reload(world, old, fresh)` takes the packs the world runs on and answers `Result<SaveCheck,
ReloadRefused>`.

## Steps
The window reloads the same pack folders it started with, so these steps use a copy of the `ahead` fixture
pack (whose every definition sorts first) and change the copy on disk.

1. Make the copy without its spell, and seal it:
   ```
   rm -rf /tmp/ahead && cp -R crates/omnis-sim/tests/packs/ahead /tmp/ahead
   mv /tmp/ahead/data/spells/fire_bolt.ron /tmp/fire_bolt.ron
   cargo run -p omnis-cli -- pack seal /tmp/ahead
   ```
2. Start on it:
   ```
   just run --windowed --pack packs/base --pack packs/test --pack crates/omnis-sim/tests/packs/objects --pack /tmp/ahead
   ```
   Start a **New game**. Open the wizard's sheet and note the spells it knows (Fire Bolt among them).
3. The same packs. Esc, **Debug**, the **World** tab, **Reload packs**.
   *You will see* the log read "Packs reloaded: the same packs".
4. Reload by name. In a terminal, put the spell back and seal:
   ```
   mv /tmp/fire_bolt.ron /tmp/ahead/data/spells/fire_bolt.ron
   cargo run -p omnis-cli -- pack seal /tmp/ahead
   ```
   Press **Reload packs** again.
   *You will see* "Packs reloaded: loaded by name. The world has moved on". Close the panel and open the
   wizard's sheet: the same spells as in step 2. (Before 7h5 every spell after `ahead`'s would have shifted
   one place: the wizard's Fire Bolt would have read as another spell.)
5. The refused reload. Esc, **Debug**, the **Party** page: choose **Item**, the first entry (**Dagger**,
   `ahead`'s), Count 1, **To stores**. Then take the dagger out of the pack and seal:
   ```
   mv /tmp/ahead/data/items/dagger.ron /tmp/dagger.ron
   cargo run -p omnis-cli -- pack seal /tmp/ahead
   ```
   On the **World** tab, press **Reload packs**.
   *You will see* the Load screen:
   - "These packs do not load";
   - "The world names what the reloaded packs no longer have. Nothing changed.";
   - "Packs changed:", then "ahead: running 0.1.3, reloaded 0.1.4" (each seal raises the patch number);
   - "Missing:", then "item 'ahead:item:dagger' in party.inventory";
   - a **Close** button.
6. Choose **Close**.
   *You will see* the Debug page again. The dagger is still in the party's stores: nothing changed.
7. Optional, by MCP: ask me for `pack_reload`.
   *You will see* in my answer the same refusal, listing the dagger. Put the dagger back
   (`mv /tmp/dagger.ron /tmp/ahead/data/items/dagger.ron`, then seal) and ask again: the answer is `done`, its
   `check` with the verdict `content`.
8. Quit, and remove the copy: `rm -rf /tmp/ahead /tmp/dagger.ron /tmp/fire_bolt.ron`. Nothing in the
   repository changed (`git status --short` lists only your untracked files).

## What the tests cover
- **`omnis-sim/tests/reload.rs` (8):**
  - written first: a reload adding `ahead` keeps every view and every named thing the same while exploring
    (after a fight), mid-fight, in town (smith, bank, inn) and in the yard; the world folded, its journal held
    for the old folder; saved, it loads back as the same world;
  - a reload lacking a carried name is refused with the report and the message, and nothing changes;
  - the same packs answer `same` and change nothing;
  - other content records the packs, keeps the journal, changes nothing else, and its next save loads;
  - a reload walling the party in moves it to the nearest cell it can stand on, with the warning, and its
    next save loads.
- **`omnis-sim/tests/ops.rs`:** the host ops' rules: a reload records the packs (`content`); one whose map is
  gone is refused with nothing changed.
- **Client (`omnis-vector/tests/load_report.rs`, 3 more):** Reload packs fits the running game by name and
  says so, the party view the same; a reload lacking the dagger opens the Load screen with its rows, changes
  nothing and closes to the Debug page; the log's words for each verdict and place count. The Debug page's
  Reload packs is the host's (`debug.rs`).
- **Socket, CLI, MCP:** `pack.reload` answers `done` with the check (`same`) and the log says it; the
  headless driver's report names the packs; `done` without `check` still reads.
