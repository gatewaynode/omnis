# Acceptance: the document model (M5.2)

The second step of M5 Editor v1 (`tasks/plans/m5-editor-v1.md`): `omnis_data::edit`, the Bevy-free model every
later step stands on. Nothing the player sees changes; nothing in the shipped packs changes. What the owner can
try is the test run, and from M5.3 the same model through MCP tools.

## What was built (`crates/omnis-data/src/edit/`)
- `Grid` (`grid.rs`): one level as tiles (a terrain index or no ground), edges (open, wall, door, ramp) and heights.
  A layout read in and written out is the file's rows byte for byte: proven on all eleven level grids the
  repository holds (the four test maps, the tower's four levels, the hills with its heights rows, the yard's two).
  Heights are written one way, right-aligned to the widest number and one space apart, which is how `hills.ron`
  was written by hand.
- `Document` (`document.rs`): the map with its grids held apart, one `Arc` per level, so a snapshot copies only
  the level a change touched (a hundred snapshots cost a hundred grids, not a hundred maps). Every change works on
  a copy and lands whole or not at all; a stroke of paints undoes as one step; `UNDO_CAP` 100. Brushes: a terrain
  (a stair up or down needs its rise and keeps the `stairs` list consistent: painting over a stair drops its
  entry), an edge (the boundary stays a wall), a height, no ground. Placements upsert by key and remove by target.
  Edits: resize (top-left kept, what falls outside dropped, the start clamped), the map's fields, levels added
  (all no ground) and removed (with everything on them), terrains added, changed (a rename carries its rest
  events; a join change while in use is refused) and removed (while unused; the tiles above reindex), a stair's
  rise. `validate(Some(&data))` is the loader's verdict through `MapData::resolve`.
- `Session` (`session.rs`, `files.rs`, `notes_store.rs`): the roots loaded, the last edited. `maps()`, `open(id)`,
  `new_map` (the pack's own id and a free file), `status`, `save` (refused with the loader's words while the map
  would not load, nothing written; otherwise the file is written atomically and the pack resealed at the next
  patch version, the owner's choice), `files()`, `read`, `check` (by directory, through the loader's own
  functions: `pack.ron`, every `data/` kind, `text/<lang>`, `notes`, `migrations`; anything else refused),
  `write` (as typed, once the check is clean, then resealed, except a notes file). The notes store: `notes/*.ron`
  read once, a note written at once into its map's file or its kind's, never sealed; `orphaned_notes` lists the
  keys whose target is nowhere.

## Steps
1. `cargo test -p omnis-data --test integration edit_`
   *You will see* 23 tests pass: 7 on the grid (byte-for-byte on the eleven grids among them), 10 on the document,
   6 on a scratch copy of `packs/test` (the save refused and nothing written; the save that reseals at 0.1.2 and
   loads again with the map as edited; a new map named in a region through the RON view; every file read and
   checked clean, a broken one refused with its line, a comment kept; notes written, orphans told apart, the
   seal untouched).
2. `git status`
   *You will see* nothing changed under `packs/`: the tests write only under the target directory.
3. `cargo run -p omnis-cli -- validate packs/base packs/test`
   *You will see* `ok:` as before.

## Not in this step
The ops and MCP tools (M5.3) and the client (M5.4 on). The `Document` is reachable only from Rust until M5.3.
