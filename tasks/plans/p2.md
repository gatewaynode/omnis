# Plan: parity P2 — the screen kit, then title, new game, pause, save and load, defeat

## Context
P2 is the first parity step after the presentation architecture v0.4 (`presentation-ARCHITECTURE.md`), which
the owner accepted on 2026-10-10. It has two halves:
- **The screen kit.** The owner chose Bevy-free screen descriptions with an `apply` function, drawn by one
  renderer (VA10). They ask that every later parity screen be built on it.
- **The game's front door.** Today `omnis-vector` starts straight into the town with seed 1, a fixed party,
  `Settings::default()` (devtools off), and no way to save, load, pause or return to a title. `omnis-app` has
  a title screen, a new-game form, pause, save and load (one quick-save slot) and a defeat screen. P2 brings
  those over, with their details (§6.7 of the architecture, and the survey of `omnis-app/src/menu.rs`,
  `menus.rs` and `sim.rs`).

**Findings that shape the plan:**
- **The shell assumes a world from the first frame.** `Session::start` runs in `main` before the App is
  built (`main.rs:34`). Fifteen `Update` systems take `Res<Session>` or `ResMut<Session>`, none with a run
  condition: `movement::advance`, `render::{rebuild, follow, draw}`, `hud::status`, `minimap::repaint`,
  `controls::press`, `panel::{keys, choose, refresh}`, `combat::{track, input, refresh}`, `socket::serve`, and
  `host::handle`. A title screen has no world, so these must stop assuming one.
- **The widgets are already compiled** (resolves architecture §15.1). Bevy's `ui` feature includes
  `bevy_ui_widgets` (in the lock already, no new crate). It provides the unstyled `EditableText` (from
  `bevy_text`; keyboard, mouse and IME input through `EditableTextInputPlugin`; a `TextEditChange` event),
  `Slider` (`ValueChange<f32>`), `Checkbox`, and `ScrollArea`. `TabNavigationPlugin` is not in
  `DefaultPlugins`. P2's seed field uses `EditableText`; the later steps use the slider and checkbox.
- **Four copper-as-gold bugs**, the same family as the bribe-label fix (`c9aac59`):
  - `shell/text.rs:26` and `rolllog.rs:174` print `Bribed.cost` (copper) as gold.
  - `shell/text.rs:31` and `rolllog.rs:326` print `CombatEnded.gold` (copper) as gold.

  `docs/api.md` §9 says both are copper. `omnis-app` prints `gp_floor`. Separately, `Event::Message`
  prints `{key:?}`, the Rust debug form.
- **Esc has three owners today:** `panel.rs:92` closes the action menu, `render.rs:115` releases mouse look,
  and `combat.rs:181` steps the fight menu back. A pause on Esc needs one router to decide.
- **Save and load are already written for the socket.** `shell/host.rs:26-41` does `client_path`, then
  `SimWorld::save_text` (the engine's save rule), `read_text` (the loader's limits), `load_text`, and
  `Session::replace`. The player's save and load reuse these, moved into one Bevy-free place.

## Decisions taken in this plan (defaults; tell me if any is wrong)
- **New game keeps the fixed party until P3.** Start creates the world from the form's seed and settings,
  then the four drafts of `party::fixed()`. P3 puts character creation in that slot.
- **The window starts on the title.** `--seed N` starts straight in the game, as `omnis-app`'s unattended
  rule does, so `just run --seed 7` and the tests keep their direct start. So does `--screenshot`, unless
  `--screen` names another screen.
- **One quick-save slot**, `.omnis/quick.ron`, overridable with `--save <file>`; checked by
  `client_path`. This matches `omnis-app`. More slots are a later item.
- **Pause has only P2's items:** Resume, Save, Load, Save log, Quit to title, and Quit set apart. Sheet (P6),
  Debug (P8) and Settings (P8) are added when their screens exist, never as dead buttons.
- **Defeat** offers Load last save (dim with the reason when there is no save file), Start again (same seed
  and settings) and Quit to title. Defeat is the views' "no member can fight", as today, so a loaded save of
  a wiped party also lands on it.
- **Devtools worlds in devtools builds:** `Settings.devtools = cfg!(feature = "devtools")` at every start, as
  `omnis-app`'s `game_settings` does. `time.reconcile` and `Dev` then work over the socket. The pause screen
  shows it.

## P2a. Labels and the money bugs (Bevy-free)
- **New `src/labels.rs`.**
  - Name lookups from string ids, via `data.registry` and `Data::label("en", ..)`: `item`, `spell`,
    `monster`, `condition`, `service`, `map`.
  - `message(key)` looks up a `MessageKey`'s text key.
  - `coins(cp)` gives "15 gp 3 sp 7 cp", ported from `omnis-app/src/text.rs:261`. `gold(cp)` gives whole
    gold, through `omnis_core::money::gp_floor`.
  - The save rule's labels ("Anywhere", "Inns, items, and spells", "Inns only"), from `omnis-app`'s
    `rule_label`.
- **Every existing `data.label("en", ..)` call goes through `labels`.** About ten, in `combat_menu.rs`,
  `rolllog.rs`, `arena.rs` and `shell/town.rs`. Afterwards it is the only module that reads text from
  `Data`.
- **Fix:** the bribe and victory lines in `shell/text.rs` and `rolllog.rs` use `labels::gold`. `Message`
  uses `labels::message`.
- **Tests:**
  - A red-first test per bug: the golden fight, or a `Bribed { cost: 5000 }` event, reads "50 gold".
  - Labels for an id from each registry. An unknown id falls back to the id itself, never a panic.
  - `coins` at 0, at 1 cp and at a mixed amount.

## P2b. The screen kit, and the centre panel moved onto it
- **`src/style.rs`, the seam the style step fills (§7):**
  - `Role { Interface, Dim, Alert, Title }` with a default ink each. Today's `controls.rs` `GREEN`, `SHADES`
    and `DIM` move here.
  - `Size { Title, Body, Small }` as fractions of the window's height, replacing the inline 22, 18, 16 and 15.
  - Not in P2: 3D, arena, minimap and cinema colours. They stay until the style step.
- **`src/screen/mod.rs`, the description (architecture §6.1, §6.2):**
  - `Screen { id, title, panels, keys, message }`, `Panel`, `Row`, `Span { text, role, size }`.
  - `Control { id, label, kind, why_not }` with `Kind { Button, Toggle(bool), Choice { options, at }, Text { value, max } }`.
    `Choice` is a left/right cycle, as the save rule needs. Number and Slider come with P3, P4 and P6.
  - `Payload { Press, Text(String), Left, Right }` and `Effect { None, Command, Host(HostOp), Go(ScreenId), Back, Restart, Quit, QuitToTitle }`.
  - `HostOp { NewGame { seed, settings }, Save, Load, SaveLog }`.
  - The shape hash.
- **`src/screen/nav.rs`:** `Nav { base, stack }`.
  - `base_for(views)`: Explore, Service, Fight or Defeat. Title and NewGame when there is no world.
  - `push` and `back`.
  - `settle(views)` closes the overlays the mode no longer allows: a fight closes Actions and Pause's
    children; a loaded save resets the stack.
  - `escape()` decides Esc, in this order:
    1. The top overlay's Back.
    2. A fight's menu back-step when not at its root.
    3. Pause from the Explore, Service and Fight bases.
- **Screens moved from the centre panel onto the kit**, with the same content and tests:
  - `screen/actions.rs` (from `shell/actions.rs`; the overlay Space opens)
  - `screen/service.rs` (the V2 stopgap notice from `shell/town.rs`, until P4)
  - `screen/defeat.rs` (from `shell/fight.rs`, extended below)
  - `shell/panel.rs`, `notice.rs`, `actions.rs`, `town.rs` and `fight.rs` are deleted. The digit keys stay
    shortcuts, through each screen's key table.
- **`shell/screen.rs`, the renderer and the router (§6.4):**
  - **Render.** Each frame the renderer builds the top screen's content. It spawns `bevy_ui` nodes under a
    `ScreenRoot` when the shape hash changes, and otherwise rewrites the text in place.
    - A control is drawn through `controls::button`'s styling, moved into the renderer.
    - `why_not` draws dim with "label: why" and no `Button`, as today.
    - `Text` spawns an `EditableText` with `max_characters`.
    - `Choice` draws as "‹ value ›" with left and right hit areas.
  - **Route.**
    - `Interaction::Pressed` on `Control(id)` becomes `Payload::Press`.
    - `TextEditChange` on a text control becomes `Payload::Text(value)`.
    - Left and right on a `Choice` become `Payload::Left` and `Payload::Right`.
    - The screen's key table, with Esc going through `Nav::escape`.
    - The screen's `apply` then returns an `Effect`, and one system carries it out.
  - The renderer and router run in a new `VectorSet::Screens`, between `Grab` and `Input`, and always run.
- **The fight screen's own controls are untouched until P7.** `Nav::escape` asks `CombatMenu` whether it is
  at its root, so Esc steps back first and pauses second.

## P2c. No world until there is one; title, new game, pause, save and load, defeat
- **`Packs` and `Session`.**
  - A new `Packs { data: Arc<Data>, config }` resource is loaded in `main` and always present. A pack error
    exits as today.
  - `Session` exists only while a game runs. `Session.data` becomes `Arc<Data>`; call sites deref
    unchanged.
  - New constructors: `Session::new_game(packs, seed, settings)` (the world plus the fixed party, logged) and
    `Session::load(packs, path)`. Both are Bevy-free, and both return the refusal text on failure.
  - `Session::start(config)` stays for tests and for `--seed` and `--screenshot` starts.
  - `restart()` keeps the current seed and settings.
- **Run conditions instead of panics.**
  - `ShellPlugin` gives `VectorSet::{Grab, Input, Move}` the condition `resource_exists::<Session>` and not
    paused. Paused means the top screen is an overlay that blocks: Pause, Defeat, NewGame.
  - `VectorSet::Draw` runs whenever a `Session` exists, so the scene stays drawn behind Pause.
  - `combat::track` moves under the same condition.
  - `socket::serve` takes `Option<ResMut<Session>>` and answers every op with `OpError::Failed("no game is
    running; start one from the title")` when there is none.
  - The cameras, HUD and minimap spawn at Startup as now and show nothing without a session. The HUD
    status is hidden at the title.
- **The screens (Bevy-free; details from `omnis-app`):**
  - **`screen/title.rs`:** "OMNIS", then New game, Load quick save (dim "no save at .omnis/quick.ron"
    when the file is missing), and Quit. A failed load shows "Load failed: …" in the alert role.
  - **`screen/new_game.rs`:**
    - The seed field: 32 bytes at most, and "blank = random, words are hashed".
    - Saving: ‹ rule › over Anywhere, Relief and InnOnly. Permadeath: ‹ On/Off ›. Start and Back.
    - `seed(text, entropy)` trims the text. A blank seed uses entropy. A number is used as typed. Any other
      text is hashed with `omnis_core::rng::fnv1a64`.
    - Entropy comes from the shell: `SystemTime`, mixed by `splitmix64` as `omnis-app/src/lib.rs:117`
      does, and is an input to `apply`, so tests pass a fixed value.
    - The form's state persists across Back.
  - **`screen/pause.rs`:**
    - "PAUSED", "Seed N", "Saving: <label>", "Permadeath: on/off", "Devtools: on/off".
    - Resume, Save (dim with "The save rule forbids saving here" when `!here.may_save`), Load (dim when
      there is no save file), Save log (dim with the `unreplayable` reason), Quit to title.
    - Quit is in its own row, set apart (PRD §7).
    - Messages: "Saved to …", "Save failed: …", "Loaded …", "Load failed: …".
  - **`screen/defeat.rs`:** "The party has fallen", the last four roll-log lines (or "Every member is
    down."), Load last save, Start again, Quit to title.
- **Host ops (`src/game_io.rs`, Bevy-free):** `save(world, root, path)` and `load(packs, root, path)`.
  Both reuse `client_path`, `SimWorld::save_text`, `read_text` and `load_text`. `shell/host.rs`'s
  `save.write` and `save.read` call them too, so the socket and the pause screen share one path. A load
  goes through `Session::replace`, which marks the log as no longer replaying, as the socket's does.
- **The controls corner:** Save log moves from the right-hand corner into Pause. The corner keeps Actions
  and a Menu button, which opens Pause (buttons first, since Esc is a key). Quit moves into Pause. The fight
  screen's right-hand Save log and Quit are replaced by the same Menu button.
- **CLI (`session.rs` `parse`):**
  - `--save <file>` (relative, through `client_path`).
  - `--screen <title|new-game|pause|actions>`, for captures and for starting the window on a screen.
  - `--seed` now also means "start in the game". The default start is the title.
  - `--log` is unchanged.
  - `README` and `just run`'s help line note the title.
- **Capture (`capture.rs`):** with `--screen`, `drive` opens that screen on frame 1, then settles and
  captures as now. `--screen title` without `--seed` captures with no world.
