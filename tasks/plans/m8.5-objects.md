# M8.5 step 2: objects, ground items and visible beings

Saved 2026-10-14 from the plan approved by the owner the same day. Each item is one commit; tests are written red first.

## Context
On 2026-10-14 the owner settled the editor's direction: objects come first, defined in data and the engine as
hand-written RON, and Editor v1 (M5) follows. Step 2 gives each thing in a cell a position inside the cell.
Today nothing stands in a cell. Doors and walls sit on edges, fixed encounters are unseen trigger cells, there
are no ground items, and loot is gold only. Owner answers (2026-10-14), all binding:

| Topic | Decision |
|---|---|
| Scope | Scenery, items on the ground, visible beings |
| Interaction | The full editor-v1 §E schema: states, 13 verbs, requirements, effects, attributes, hidden, `once` |
| Look | Shape primitives per kind (box, post, slab, arch, sign, heap; figure for beings), each with a width, depth and height in eighths, drawn as lines over a dark fill. Line-model set pieces stay open (§12.4) |
| Position | An offset from the cell centre in eighths (−4..=4 east, south), a facing that turns the footprint, and a level. A footprint may spill into the next cell; the loader refuses a spill through a wall or door, or onto no ground |
| Blocking | Per footprint. A step's path is a corridor 4 eighths wide between the two cell centres. A blocking footprint in either cell that overlaps it stops the step (`BlockReason::Object`). Sight rays test sight-blocking footprints, using each object's height |
| Beings | A fixed encounter stands visibly at an offset. Entering its cell starts it, as today; Use on it also starts it. No wandering. Random encounters are unchanged |
| Ground items | From four sources: placed in the map; Drop and pick-up by the party; inside containers; monster loot (shared `data/loot` tables that a monster names), which lies on the fight's cell after a victory. Gold is unchanged |
| Verbs | Use runs the single available action at once. When there are several, the client lists one button per verb, each showing its refusal reason. Mouse first |
| Automap | No objects on the automap or minimap yet |
| Hidden | Found three ways: by passive Perception when in sight within a few cells, by Search on the cell, and by a reveal spell. Detect Magic is a lasting concentration effect, like Light |
| Content | The fixture only. The base pack gains Detect Magic; base monsters get no loot; `packs/test` is unchanged |
| Cut | 2a data and engine, 2b client, 2c beings. Each sub-step gets its own acceptance script |

Found during research, and fixed first: `omnis-sim/src/encounter.rs:110` builds the retreat position on
`Level::GROUND` instead of `from.level`. So Run or Flee from an encounter on any other level drops the party
to level 0.

## Design

### Data (`omnis-data`, integers only)
- **Ids:** `ObjectKindId` and `LootTableId` (`omnis-core/src/id.rs`, `define_id!`).
- **`object.rs`**, with validation in `object/check.rs`:
  - Enums:
    - `Verb` (13 variants)
    - `Shape { Box, Post, Slab, Arch, Sign, Heap }`, plus `Figure` in 2c
    - `Material`
  - `Look { shape, width, depth, height }` in eighths. Width and depth are 1..=8; height is 1..=32.
  - `Attributes`:
    - `blocks_movement`, `blocks_sight`
    - `size`, `material`, `weight_tenths`
    - `capacity`
    - `light`, `noise`, `smell`, `value_cp`
    - `tags`
    - `aura: Option<School>`, which Detect Magic senses
  - `StateDef { look?, blocks_movement?, blocks_sight?, open }`
  - `Requirement`:
    - `Skill{skill, dc}`
    - `Ability{ability, dc}`
    - `Item{id, consume}`
    - `Flag{name, min}`
    - `School`: a living member knows a spell of that school
    - `Rule{slot}`, with inputs `party_level` and `party_size`
  - `Effect { SetState, SetFlag, Message, GiveGold, GiveItem, Remove }`
  - `Interaction { verb, label?, when_state?, requires, effects, failure?, once, minutes? }`
  - `ObjectKind { schema, id, name, look, initial_state, states, attributes, interactions }`
  - What does nothing yet, as §E said, and the docs will say so: size, material, weight, light, noise,
    smell, value and tags.
- **`placement.rs`:**
  - `MapDef.objects: Vec<Placement>` and `MapDef.ground: Vec<GroundDef>`, both `serde(default)`.
  - `Placement { id, kind, level, x, y, pos: (i8,i8), facing, state?, hidden?: dc, name?, contents }`.
    - Ids are `[a-z0-9_]{1,32}`, because `world.query` paths split on `.` and script words split on `-`.
    - The offset key is `pos`, because `at` is banned and `offset` is already taken.
  - `MapData` gains `objects`, `object_cells` (every cell a footprint touches) and `ground`.
- **`loot.rs`:**
  - `LootTable { schema, id, picks, entries: [LootEntry { item, count: Dice, weight, chance_percent }] }`
  - `Monster.loot: Option<String>`
- **`footprint.rs`:** the shared integer geometry, used by the engine and by the client's mirror.
- **Limits:**

| Limit | Value |
|---|---|
| Objects per cell | 16 |
| Objects per map | 4096 |
| States | 16 |
| Interactions | 16 |
| Requirements | 8 |
| Effects | 16 |
| Tags | 32 |
| Object height | 32 |
| Capacity | 64 |
| Pile stacks | 32 |
| Loot entries | 64 |
| Loot picks | 8 |
| Check DC | 30 |

  Every load check gets a bad-pack row in a new `tests/packs-bad/bad-objects`. Among the refusals: a blocking
  footprint over an arrival centre (start, portal landing, join landing, site, encounter), and a hidden
  object that blocks.
- **Refactor first:** `MapData` moves from `loader.rs` (866 lines) to `map_data.rs`.

### Geometry (sixteenths of a cell; the centre is at 16x+8)
- **Footprint:** the half-extents are (width, depth), swapped when facing east or west. The centre is
  (16x+8+2·ox, 16y+8+2·oy).
- **Corridor:** the centre-to-centre segment with a half-width of 4. It overlaps a footprint by open
  intervals, so touching edges don't block. Only footprints listed at the two cells on the step's level, and
  not removed, count.
- **Sight:** inside `visibility::walk`. The ray is scaled to s16, slab-clipped against each footprint, and
  compared as fractions cross-multiplied in i64.
  - The ray is blocked if `Sight::below(top, t)` holds at t0 or at t1, where `top` is the home floor plus the
    object's height.
  - Footprints listed at the origin cell and at each walked cell are tested; those whose home is the target
    cell are not.
  - Magnitudes stay below 2^54.

### Save and protocol (protocol 2, additive)
- **Save:**
  - `MapState.objects` (id → `ObjectState { state?, removed, used, noticed, contents? }`) and
    `MapState.ground` (piles).
  - `CombatState.loot`.
  - An `object` RNG stream, created on first use.
  - Every new field is skipped when empty, so `SAVE_SCHEMA` stays 7 with no migration. A save with no
    objects is byte-identical, so the replays don't move.
- **Commands:**
  - `Command::Act { object, verb }` and `Command::Search`.
  - `ItemCommand::{Drop, PickUp}` (`Take` already means stores to kit), and `ItemCommand::{TakeOut, PutIn}`.
- **Events:** `ObjectUsed`, `ObjectState`, `ObjectRemoved`, `ObjectMessage`, `GoldFound`, `Noticed` (passive,
  search or spell) and `Searched`. Loot goes on `Death` and on `CombatEnded`.
- **Rejections:**
  - `NoSuchObject`, which also covers hidden, removed and out-of-reach objects, so nothing leaks;
  - `VerbRefused` with a `Refusal`;
  - `ChooseVerb`;
  - `NotOnGround`, `NotInObject`.
- **Other additions:**
  - `BlockReason::Object`; `CheckKind::Skill/Ability`.
  - The `objects.get` op and the MCP tool `objects_get`.
  - `ViewportModel.objects` and `.piles`, plus `.beings` in 2c.
- Each name is checked against the vocabulary test before use (lesson 2026-10-10). Keys to watch: `kind`
  (use `object_kind`), `gold`, `state` and `loot`.
- `ItemPlace` gains `Ground` and `Object`. If `Copy` must stay, the object reference becomes an index or a
  separate event; that is decided when building it, and named in the commit.
- **Interact:**
  1. A service on the party's own tile wins, as today.
  2. Otherwise the candidates are the faced door, objects' available verbs in the party's own cell, and those
     in the faced cell when the edge between is open.
  3. One candidate runs at once; none gives "Nothing here"; several give `ChooseVerb` and change nothing.

## Decided by me unless the owner objects (each named in the plan file)
- `Requirement::School` means a member knows a spell of that school.
- Rule slots get `party_level` and `party_size`, both over the members who can act: the mean level
  rounded down, and how many there are (item 9).
- `Command::Act` carries `option` (default 0) as well as the verb: the chest offers two Opens (force,
  pick), so a verb alone does not name one (item 9).
- Requirements are members who can act (`can_fight`) throughout: the School holder, the check roller.
- An item that is used up comes from the stores first, then a spare in a kit; a worn or wielded one is
  never used up, and does not count as carried for a `consume` requirement (item 9).
- Events added beyond the plan's list: `ItemFound` and `ItemSpent` (item 9); a set flag has no event.
- A loot table draws `picks` entries by weight, then rolls each entry's chance.
- Door and object together give a list, not door first.
- `ChooseVerb` carries its `choices`, each the command that does it (`Choice::Door` or `Choice::Object { object,
  verb, option }`): the door first, then objects in the party's cell before the faced one, each kind's order.
  A `once` already spent is not a choice; one refused by a requirement is, and run alone it says why (item 10).
- Ground and containers (item 11): pick-up reaches the party's own cell only; Drop, PickUp, TakeOut and PutIn
  take no time (as Stow and Take), need a member who can act, and work only while exploring. A container is
  open in a state marked `open`, or always when its kind has no states; capacity counts kinds of item, as a
  pile's 32 stacks do. A shut one is `Refusal::Closed`, a full one `Refusal::Full`, a non-container
  `NotOffered`; a full pile is the new `Rejection::PileFull`. `ItemPlace::Object` carries the placement id,
  so `ItemPlace` is no longer `Copy`. The client says "drops", "picks up", "puts … in", "takes … out" now
  (needed for exhaustiveness); 2b item 5 may reword them with the object's name.
- Loot (item 12) rolls on the `combat` stream at each death (no new stream), so a fight's dice are one sequence;
  it lies at the centre of the fight's cell, or joins a pile there, and may hold more than a dropped pile's
  32 kinds. `Death.loot` and `CombatEnded.loot` are `[Loot { item, count }]`, left out when empty. A dev kill
  rolls no loot, as it rolls no gold.
- Hidden objects (item 13): `Command::Search` is an enum value beside `Interact` in the MCP schema, so `oneOf`
  stays 13 (the plan said 14). A search with no member able to act is `VerbRefused { NoneCanAct }`. A reveal
  needs no sight (the SRD's detect magic passes most barriers) and is checked before the eye; it is not cast
  in a fight (as mage hand). `notice_tiles` and `search_minutes` default in code (2, 10) until item 14 adds
  them to the base pack with Detect Magic, so the replays move once. HUD lines for `Noticed`/`Searched` wait
  for 2b item 5, which needs object names.
- `Command::Door` (word `door`, refusal `NoDoor`) is added beyond the plan's list, so a door listed beside an
  object can be chosen; it costs the minute Use on a door costs (item 10).
- A low sight-blocker is not refused.
- The client does not push the pose out of a footprint in its own cell (visual only, later).
- Detect Magic is not sold by the guild yet.
- Detect Magic (item 14) is appended to both class lists, so a new wizard starts knowing it (the wizard may
  know six first-level spells and the list had four), and the fight replay's wizard knows one more spell. A
  cleric (two at level 1) learns it from the trainer. The v5 and v6 save fixtures, which keep spells as
  interned numbers, were renumbered for the new id (every spell number from 4 up, by one); saves keyed by
  string ids would end that, a save-schema change left to the owner.
