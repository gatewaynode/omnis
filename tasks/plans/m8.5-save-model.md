# Plan: the save model (PRD D28), M8.5 step 7 reshaped

Approved by the owner 2026-10-17.

**Amended 2026-10-17 (owner), after 7d was first built:** a load does not replay. The first 7d saved the party at
the base plus every command and replayed them on load; the owner rejected that: CRPG loads of 4–5 s are normal, so
a one-second budget sized nothing real, and movement changes nothing in the world besides time, so a save
captures interactions, not moves. Now:
- the character save holds **the party as it stands** (the checkpoint taken at the save);
- the journal holds **interactions only**: a command that changed what the world holds (map states, world flags,
  the clocks, contacts and streams of holders other than the party), with those changes as values after;
- **a load lays the changes over the bases** and runs no rule, then checks the fingerprint;
- found hidden objects and lore told once are **the party's knowledge** (`World::known`), so a step never changes
  the world.

Below, where the text says the journal is every command, or a load replays, read this. Command replay stays for
the goldens and determinism tests (A14).

## Context
Today a save is the engine's whole `World` (RON, `SAVE_SCHEMA` 7), so a character is welded to every map's state,
every clock and the RNG streams, and a pack change breaks it (the problem step 7 was planned to patch). The owner's
direction (PRD D28, §7.7; study `tasks/plans/world-state.md`, answered 2026-10-17):
- The character save holds the party and a journal of interactions since the world's last base.
- Loading replays the journal from that base.
- The world's state lives in a world directory the simulation owns: immutable authored bases, play's changes as
  layers over them, folded into new bases.

Owner answers that shape this plan:
- **Layers are derived from the journal.** The world directory holds bases only.
- **A provisional size fold** runs at safe points until M10's world sim (a simplified 4X engine) sets the
  thresholds.
- **Pre-fold history** is kept as archived events.
- **Changed packs:** migrate, then report.
- **Flags:** scoped per flag.
- **World directory:** one per world, with a file per region.
- **Folds are visible.**
- **Named bases are kept.**
- **Carrying characters between worlds** is a horizon.

Step 7 keeps its number (deferred-milestone rule) and becomes this work, in sub-steps 7a–7h. Its old content
(name table, migrations, pack seal, `save.check`) is 7h.

## Shape
- **`World.journal: Journal`**:
  - `#[serde(skip)]`, so it is not in the fingerprint.
  - `apply` appends one `Entry { minute, command }` per accepted command, where `minute` is the party's age after
    the command.
  - Each entry also keeps its events in memory, unsaved, minus `Visible` and other per-tile events, for the
    archive.
  - A replay rebuilds the journal identically, so `World: PartialEq` stays meaningful.
- **`split(&World, &Data) -> (WorldBase, BTreeMap<RegionId, RegionBase>, Checkpoint)`** and
  **`join(..) -> World`**, both pure, in a new `omnis-sim/src/save/` module (several files, each ≤ ~400 lines):
  - **`RegionBase`** holds:
    - the `MapState` of each of its maps, empty entries kept (they change the fingerprint);
    - the region's clock;
    - contacts keyed `(Region self, _)`;
    - the `time:`, `eco:` and `story:` streams that name the region.
  - **`WorldBase`** holds world-scoped flags and any holder that is neither party nor region (Actor, Character,
    Project). Those are empty today. The catch-all keeps the invariant safe when M9/M10 add them.
  - **`Checkpoint`** holds:
    - party and `party_time`;
    - the party clock and contacts keyed `(Party, _)`;
    - the other RNG streams;
    - automap and position;
    - mode and bus (the Battle→Reactions subscription during a fight);
    - party-scoped flags, settings and `turn`.
  - **The manifest** holds `seed` and `packs`.
  - `join` places each `MapState` by the current `RegionDef.maps`, reports strays, and runs `check_mode` and
    `check_party`.
- **Invariant:** `join(split(w)) == w` (equal and the same fingerprint) for every test world, including mid-fight
  and in town. Also `World::new == join(base 0, default checkpoint)`.
- **On disk** (host I/O, `omnis-vector/src/game_io.rs` and the CLI headless host):
  - **The world folder** `.omnis/worlds/<world>/` holds:
    - `manifest.ron`, which lists every base and the saves naming it;
    - `world/<hash>.ron`;
    - `regions/<region>/<hash>.ron`, where `<region>` is the sanitized string id.
  - **Base ids** are fnv64 of the base's RON. Base 0 is the authored pack and has no file, so a region never
    touched has no file.
  - **Writes** go to a temp file, then a rename; the manifest is written last and checked on load.
  - **Saves are character saves:**
    `.omnis/saves/<name>.ron` = `CharacterSave { schema: 8, world, bases, checkpoint, journal, fingerprint }`.
  - **The archive** is `<name>.archive/<n>.ron`, one segment per fold.
  - **Base cleanup** is a manual tidy action that drops bases no save names, never automatic on write (saves are
    the player's files). This departs from "dropped" on timing only.
- **Registry numbers:** checkpoint and bases carry them until 7h, so loading keeps today's `PackMismatch` gate
  until then.
- **Fold:**
  - **Triggers:** apply's end of command, a story point (M11), the provisional size rule, or `DevCommand::Fold`.
  - **Effect:** a new world base and region bases for the regions the journal touched, a new checkpoint, the
    journal's events moved to the pending archive segment, the journal cleared, and `Event::Folded`.
  - **The host** writes the new bases at once (the world folder is the simulation's).
  - **The provisional rule:** at a safe point (after a long rest, or entering a settlement), when
    `journal.len() > rules.fold_journal_entries`, fold and show "The world has moved on". The value comes from
    7a's measurement.
- **Loading:**
  1. Read the save.
  2. Join its named bases with the checkpoint.
  3. Replay the journal entry by entry.
  4. Verify the fingerprint when the packs are unchanged and nothing was skipped. Otherwise report: refused
     entries (index, command, rejection), "the outcome may differ", load or cancel.
- **The client History** is rebuilt from the archive segments, then the journal is replayed one entry at a time
  through `take_in`. Lines from `say()` that have no event behind them are lost.
- **Saving mid-fight stays allowed.** It is tested, and the journal makes it cheap. The study's "no saving in a
  fight still stands" is corrected.
- **A v7 save** loads by folding at load: its `MapState`s become bases and the rest becomes the checkpoint, with
  an empty journal and a "converted" report.

## Sub-steps (each ends in something the owner can see or click, each with its acceptance script)
- **7a. Journal and measurement.**
  - Build: `World.journal`, appended in `apply`.
  - Measure:
    - a timing harness, `omnis replay --time` plus a release-mode ignored test, that drives a seeded wandering
      party for 10k/50k commands on the test packs;
    - µs per command for apply and replay;
    - journal bytes per entry;
    - commands per hour, from the owner's play (`save_log`).
  - Visible: the debug World page shows the journal's length and "replay would take ~T ms".
- **7b. `split`/`join` in memory, with the invariant tests.** Covers every golden replay, the mid-fight, town and
  encounter tests, and `World::new`. Visible: the dev op `world.split` lists each region's base size and the
  checkpoint's size, with "round trip ok".
- **7c. Flag scope.** Pack data declares the scope: party flags in the pack's `flags` file, undeclared flags default
  to world. The loader validates. `split` routes flags by scope. Visible: the debug panel lists flags as party or
  world.
- **7d. Character save and world folder on disk:**
  - the new `save.write`/`save.read` semantics (`docs/api.md` changelog, additive under protocol 2);
  - v7 conversion;
  - load by laying the journal's changes over the bases (amended above), with the report;
  - the `SAVE_SCHEMA` 8 fixture, with v1–v7 fixtures still loading.

  Visible: `.omnis/worlds/<w>/` appears. Loading says "N interactions applied in T ms", or "converted" for an old
  save.
- **7e. Fold:**
  - `DevCommand::Fold`, `Event::Folded`, the HUD line "The world has moved on";
  - a fold applies the journal into new bases and archives its entries;
  - the provisional size rule at safe points, by the journal's bytes, not load time;
  - archive segments;
  - kept named bases, with an older save restoring its own moment;
  - the manual tidy action (CLI `omnis world tidy`, plus a dev op).

  Visible: fold in the yard, save, keep playing, load the older save, and the yard is as it was then.
- **7f. Full log across loads.** History is rebuilt from the archive and the journal. **Open:** what changes only
  the party (a fight won against a random encounter, a purchase) leaves no journal entry, so History needs the
  party's own chronicle; its shape is decided in 7f. Visible: quit, load, press L, and the whole history is there
  in the current language.
- **7g. Docs and pins:**
  - **ARCHITECTURE:** §4.1 (save shape), §4.9 (saves vs API), §6.2 (save limits: journal, archive, base files
    under the 4 MiB file limit), §11 A14;
  - **`docs/api.md`, MCP and counts:** `docs/api.md` and the MCP schema and proof (`Event` 73, `DevCommand` +1,
    `dev_schema`), `api_doc.rs` pins;
  - **notes:** `code-map.md` and `horizons.md` (co-op over one world needs shared stored layers; the character
    import);
  - **PRD:** a note on the tidy timing.
- **7h. Step 7's old plan, re-scoped:**
  - the name table and remap for the checkpoint and bases;
  - required fixed-encounter ids;
  - the pack hash seal;
  - declarative migrations applied to the journal's ids and to the bases; a change naming something the packs no
    longer have is reported and skipped;
  - `save.check` merged into the load report;
  - `pack.reload` through the same remap;
  - the `PackMismatch` gate lifted.

  `tasks/plans/m8.5-saves-by-name.md` is updated, not replaced.
