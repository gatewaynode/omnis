## The shell decision
The fight's controls become `ScreenId::Fight`, a `Screen` that **`shell/combat.rs` draws and routes itself**, as `shell/roster.rs` does the party column. It is never on the Nav stack (`Nav::base` stays `None` in a fight).

**Why not as Nav's base:**
- `paint` builds `content(top)` every frame, which would mean dozens of world-cloning trials a frame.
- `paint` centres the screen; the fight's controls need the arena's rects.
- An overlay (Sheet, Inventory, Pause) would hide the controls, and the party column hides under any non-beside screen.
- Every `base.is_none()` rule in `nav.rs` would need a fight exception.

**What the fight still shares:**
- The description model and `screen::apply`.
- The renderer (`screen_draw::build`, with scroll and scrollbar).
- `screen.text` (it walks the UI tree).
- Trial-lit controls and `labels::reason`.

**Behaviour:**
- **Overlays take input** as today: `VectorSet::Input` runs only while `screen::playing`.
- **Rebuilt only when its key changes:** the log length, the combat view, the step, the message and the size. It is never rebuilt per frame, so the trial cost stays on change.

## P7a. Engine: the spell's action cost, the fight's usable items
- **`SpellView.pay: Cost`** (`#[serde(default)]`), set from `spell.cost` in `spell_views`. The name matches `FeatureView.pay` and `KnownSpellView.pay`.
- **`CombatView.items: Vec<FightItemView>`** (`#[serde(default)]`), filled only on a member's turn, else empty.
  - `FightItemView { item /* id */, name /* text key */, count: u16, blocked: Option<Rejection> }`: the acting member's kit rows whose definition has a use, in kit order.
  - `blocked` = `validate_use(.., receiver None, fight=true)`, then `affordable(budget, Action)`, in the command's order.
  - Re-exported from `lib.rs` and `api.rs`.
  - Wire names checked against the vocabulary (no `items` field exists; `count` and `blocked` keep their types). Run the vocabulary test before the gate.
- **Tests (`omnis-sim/tests/api_views.rs`):**
  - Every spell row's `pay` is its definition's cost: Shield reads `Reaction` (Ilvara learns it), Healing Word reads `BonusAction`.
  - Item rows answer as the use would: on Durin's turn, with a potion and a spyglass in his kit, only usable rows are listed, counts match the kit, and each `blocked` equals a trial of `Use{receiver: None}`. That gives the potion `None`, the spyglass `NotUsableHere`, and the potion `NoActionLeft` with no action left.
  - The list is empty in the encounter and on a monster's turn.
  - An old `CombatView` JSON without `items`/`pay` still reads.
- **Measure** `combat_view` before and after, in release, and report it in the commit.
- **Docs:** `docs/api.md` §7.4 (`pay`, `items`, `FightItemView`), and an "Additions within protocol 2" line.

## P7b. The model (Bevy-free)
- **Bug, red test first:** the menu's step survives a turn that passed elsewhere.
  - Shown versus actual: with Cast's target list open on Durin's turn, if the turn passes by a load or an MCP order, the column asks "Ilvara casts <her first spell> on whom?", a step she never chose.
  - Fix: `fight::settle` returns the step to Top whenever the phase, round or acting member changes.
- **`combat_menu.rs`:**
  - **Read `Views`, not the world.** Signatures become `(data, game: Game)`; `game.world` is used only for trials. Time `content` for the Top and Spells steps, before and after.
  - **Turn order:** Attack, Cast, **Features**, Use, Dodge, Swap, End turn, Flee.
    - Features is dim with "has no features", or "no feature can be used now".
    - Use is lit from `CombatView.items` (no trials).
  - **`Step::Features`, `Action::Feature(u8)`.**
    - A feature row reads "Second Wind  1 use  bonus action" (uses: "1 use", "N uses", "at will"; the cost word from `labels::pay`). It is dim with `FeatureView.blocked` through `labels::reason`.
    - Cunning Action splits into "Cunning Action: swap", which goes to the target step and sends `FeatureChoice::Exchange{with}`, and "Cunning Action: hide", which sends `Hide`.
  - **Item rows** come from `CombatView.items`: "Potion of Healing x2" (`labels::count_label`), dim with the engine's refusal (spyglass: "not from a fight"), else "no one to use it on" when there is no target.
  - **Spell rows** read "Bless  1 pt". One note per row, in this order:
    1. "reaction", dim, with "declare it in tactics";
    2. the refusal;
    3. "in force", when a party or member effect is this spell from this caster (view data);
    4. "bonus action", when the bonus action pays.
  - **`Entry.note: Option<String>`** holds the dim text after a control.
  - **Refusals** go through `labels::reason` (a `trial::why` helper beside `refusal`), not the raw `Display`.
  - **Words:**
    - Top prompt: "Round R: X's turn".
    - `budget_line`: "Action a   Bonus b   Reaction r (on|off)", reactions for the acting member from `view.reactions`.
    - Picker head adds "SP s/max".
    - Encounter: "Monsters ahead: hostile" (`labels::disposition`: hostile, wary, neutral, friendly; my wording, the old client had none).
- **`labels`, `rolllog`, `shell/text`:** "Victory! N XP each, G gold" (`gp_floor`); update `tests/labels.rs` first.
- **`screen/fight.rs` (new, about 260 lines) and `screen/mod.rs`:**
  - `ScreenId::Fight`, `ControlId::Fight(FightAct)`, with `FightAct { Entry(u8), Reactions }` (indexed, as `Command` is neither `Copy` nor `Hash`; `apply` rebuilds the entries, so the index is stable within a press).
  - `Forms.fight: FightForm { menu: CombatMenu, turn }`, reset on entering or leaving a fight and in `Screens::reset`.
  - **`content`:**
    - title: the step's prompt;
    - the budget line;
    - at Top, "Reactions < on >" (`Kind::Choice`), trial-lit for `SetReactions{member, on: !on}`;
    - the entries (Top, targets and the encounter as one wrapped row; pickers one row each, with the note after);
    - keys 1–9 for the live entries.
  - **`apply`:**
    - `Entry(n)` returns `Effect::Command{close: false}`, or `None` for Open or Back.
    - `Reactions` flips the switch.
  - `place(&FightForm) -> Place::{Column, Over}`; `settle`.

## P7c. The shell
- **`screen_draw.rs`:**
  - `Mark::Fight` with a `FightPress(ControlId)` component.
  - The in-place word markers (`LabelOf`, `SpanAt`, `TitleText`, `MessageText`) are spawned only under `Mark::Screen`, so an overlay's word sync never touches the fight or the column. Today Choice and Number spawn `LabelOf` under any mark.
  - `build(.., mark)`.
- **`arena.rs`:** `picker(&Layout) -> Rect`: from the left margin to the party column's left edge, from the top margin to the log's top. That is about 1168×559 at 1600×900.
- **`shell/combat.rs`:**
  - `FightScreen` drops `menu` and keeps `screen: Option<Screen>`.
  - **`route`** replaces `input`:
    1. `settle`;
    2. a pressed `FightPress`, an arrow on `Fight(_)`, or a digit through `screen.key`;
    3. `screen::apply(ScreenId::Fight, ..)`;
    4. else an arena click calls `menu.pick`;
    5. the result is sent with `session.ordered`.
    - An accepted order clears the message (the roll log shows what happened); a refused one shows "Refused: …" in alert at the foot of the column or panel.
  - **`refresh`:**
    - At the column: the picture and title as today, plus the screen built into `l.actions`.
    - Over: no picture and no title, and the bordered panel at `picker` with `ZIndex(1)`. Group labels under the panel are skipped (`Rect::overlaps`). The log, the party column and the party's figures stay in view.
- **`shell/screen.rs`:** Esc reads and steps `forms.fight.menu` (the `FightScreen` parameter goes; the file stays about 750 lines).
