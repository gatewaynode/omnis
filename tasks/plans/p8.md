## P8a. The settings: model, file, screen
- **`src/settings.rs` (new, Bevy-free):**
  ```rust
  pub struct Prefs { pub reduced_motion: bool, pub grid: bool, pub quality: Quality, pub font: Face, pub scale: u16 }
  pub enum Quality { Low, Medium, High }   // default High: today's look
  pub enum Face { BuiltIn, Inter, Alegreya }
  ```
  - Defaults: motion on, grid shown, High, BuiltIn, 100.
  - `scale` is a percentage, clamped to 50..=200 and rounded to a step of 10.
  - `read(path) -> (Prefs, Option<String>)` goes through `ron_io::read_text` (symlinks refused, 4 MiB cap) into a
    lenient mirror (`#[serde(default)]`, unknown keys ignored), then clamps. A missing file gives the defaults with no
    note; an unreadable or malformed one gives the defaults and a note for the log. The file is never rewritten until
    Apply.
  - `write(path, &Prefs)` uses `ron_io::write_ron`.
  - **Dependency:** `serde = { workspace = true }` in omnis-vector, for the derive. It is already in the tree, so no new
    crate, and stays N-1 and pinned.
- **Path:** `Config.settings` defaults to `.omnis/settings.ron`. `--settings PATH` is checked with `client_path(..,
  &["ron"])` (relative, no `..`, `.ron`). Tests write under `.omnis/test-saves/`.
- **Shell (`shell/settings.rs`, new):**
  - The `Prefs` resource, read at start.
  - `apply_quality` runs on change: Low means no bloom and 1.0 px lines; Medium bloom 0.15 and 1.5 px; High bloom 0.25
    and 2.0 px (today). It covers both cameras and both gizmo groups. The view distance stays the terrain's (fog); the
    depth levels join the preset with X17.
- **Grid:** `render.rs::draw` skips `Floor` and `Ceiling` when `!prefs.grid`. A pure filter fn is unit-tested.
- **Reduced motion:** `yaw_delta(intent, dt, snap)` takes the whole pending turn when `snap`, and `ease(.., snap)`
  returns the target at once. Both are pure and unit-tested. Held arrow turns and mouse look are driven, so they are
  unchanged.
- **The screen (`screen/settings.rs`, new) and `ScreenId::Settings`:**
  ```
  SETTINGS
  Reduced motion   < off >
  Floor grid       < shown >
  Quality          < high >          (low, medium, high)
  Font             < built-in >      (built-in, Inter, Alegreya Sans)
  Interface scale  < 100% >          (50% .. 200%, steps of 10)
  [Apply]  [Close]
  ```
  - `Forms.settings: Option<Prefs>` holds the draft, filled from the applied settings when the screen opens.
  - `Ctx` gains `prefs: Prefs` (the applied ones), so content compares draft and applied.
  - Apply is dim with "nothing changed" while the draft equals the applied settings.
  - Apply gives a new `Effect::Settings(Prefs)`: the shell sets the resource, writes the file and shows "Settings
    saved" or "Could not save settings: {why}" on the panel (`Forms::shown`). The screen stays open.
  - Close and Esc drop the draft.
- **Nav:**
  - Settings is allowed with no game (over the Title) and over Pause.
  - It is in `paused`.
  - Opened with `Effect::Open(ScreenId::Settings)` from a **Settings** button on the Title (between Load quick save and
    Quit) and on Pause (beside Save log).

## P8b. Font and scale
- **Fonts (`shell/fonts.rs`, new):**
  - Inter-Regular and AlegreyaSans-Regular are compiled in with `include_bytes!` (as `feathers_fonts.rs`), added to
    `Assets<Font>` at startup, and held in a `Fonts` resource. Built-in is `Handle::default()`.
  - One system sets every `TextFont.font` to the chosen handle, on `Added<TextFont>` and on all text when
    `prefs.font` changes, so no spawn site changes.
  - The licences stay beside the files. presentation-ARCHITECTURE §3 notes the fonts as licensed assets, not
    dependencies (§7.4).
  - The ASCII rule for screen words stays.
- **Scale: "at 100% nothing moves."**
  - **Screen kit:** one function, `shell::ui_height(window_h, prefs) = window_h * scale / 100`, replaces the height
    passed to `Size::px` and `scaled` (rebuilds already key on the height, now this one).
  - **The fixed sizes move onto `style`:** `style::Size` gains `Hud` (18) and `Figure` (15) if needed, and the box
    lengths go through `scaled`.
    - The HUD's text and margins, the HUD buttons' boxes and labels, and the message line scale by `scale / 100` alone,
      so they are unchanged at 100% and keep not following the window's height. The rule is "fixed today, multiplied
      by the scale".
    - The fight's title, log and figure labels do the same.
  - **Arena:** `arena::layout(w, h, k)`, with `k = scale / 100`, multiplies MARGIN, TITLE, LABEL, STATUS, BUTTONS,
    ACTIONS and LOG. The picture's 492×200 image is displayed at `k`.
    - If the arena cannot fit at a large scale in a small window, `k` is clamped so the field keeps its minimum. The
      clamp is tested.
    - No `UiScale`: the arena's rects are shared by the UI nodes and the 2D gizmos, and a UI-only scale would split
      them.
  - **Party column:** width `(w*0.24).clamp(300, 640)` becomes `* k` within the same clamp scaled, with padding
    through `scaled`.

## P8c. The debug panel
- **`Views.flags: Vec<(String, i64)>`**, from `api::flags`, filled only when `here.settings.devtools` (as the old
  client).
- **Words:** `shell/text.rs` words `Event::Dev` as the old `describe()` does ("dev: Spyglass x3 to Durin", "dev: Durin
  hp 40", "dev: gold 100", "dev: teleport to … (x, y) facing north", "dev: stack 1 slain", …), with members by name
  through `Names`. This is a parity bug today: a socket `GiveItem` logs nothing. Red test first.
- **`screen/debug.rs` (new, about 450 lines) and `ScreenId::Debug`, `ControlId::Debug(DebugAct)`:**
  - **Header:** Page < Member | Party | World | Fight >; on Member and Party, Member < name >.
  - **Member:**
    - Hit points [12] of 12 [Set];
    - Spell points [2] of 2 [Set];
    - Experience [0] level 1 [Set];
    - Ability < STR > [15] [Set];
    - Condition < Poisoned > off [On / off].
  - **Party:**
    - Copper [6000] [Set];
    - Food [40] [Set];
    - Item < Spyglass >, Count [1], [To member] [To stores].
  - **World:**
    - Flag < id (now v) > [1] [Set], or a dim "The packs declare no flags";
    - Map < id (w by h) >, x [10], y [2], Facing < north >, [Go]. The form starts at the party's place; picking a map
      clamps x and y.
  - **Fight:**
    - Stack < Rats (2 of 3) >, Lead hit points [4] [Set], [Kill];
    - "No fight is on" (dim) outside a fight.
  - Numbers are `Kind::Text` limited to digits (as the bank's amount: 10 characters), parsed and saturated to the
    command's type (`fit`, as the old client).
  - A field shows its typed edit, or else the world's current value; an accepted Set clears its edit, so the field
    then reads the world.
  - **Every action button is lit by a trial of its command** (`trial::why`), so the engine's refusal replaces the old
    hand-coded greys. "type a number" covers an empty field.
  - **`DebugForm` in `Forms.debug`:** page, member, ability, condition, item, count, flag, map, x, y, facing, stack,
    and the edits. It is reset when the screen opens and in `Screens::reset`. The member is kept by `CharacterId`.
  - `apply` returns `Effect::Command { close: false }`; `Session::ordered` shows the outcome on the panel. The command
    is logged and replays like any other.
- **Opening:**
  - Pause's **Debug** button (beside Settings) is dim with "Devtools are off in this game", or "This build has no debug
    panel" without the `devtools` feature.
  - **Backtick** toggles it while a game runs with the base none (exploring, an encounter, a fight) or a service, and
    devtools is on.
  - Nav allows it there; it is `paused`; Esc closes it.
  - Measure its build: it is a Nav overlay, painted from `content` each frame, with about 12 trials. If it is over
    about 1 ms, cache the trials on the view's change.
